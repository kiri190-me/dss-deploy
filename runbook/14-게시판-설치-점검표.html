0. 이미 끝난 것

통합 로그인 연동을 끝냈다 Claude
/api/auth/login · /api/auth/callback · /api/auth/backchannel-logout 셋이 서고, 역할의 출처를 포털 하나로 정했다(2026-10-13 사용자 결정 · src/lib/auth/provision.ts). 이 사이트가 아는 역할은 MEMBER · ADMIN 둘이다.
운영 이미지 둘을 구웠다 Claude
dss-board:0.1(앱 · 398MB — 띄워서 도는 것을 확인했다) · dss-board-tools:1(마이그레이션용 · 1.04GB — DB 에 닿아 완주하는 것을 확인했다). 🔴 아직 개발 PC 에 있다. NAS 로 옮기는 것은 아래 4단계다.
compose 에 블록 둘을 주석으로 넣었다 Claude
app-board · tools-board. 🔴 주석인 채로 들어갔다 — env/board.env 가 NAS 에 아직 없어서 켜 두면 docker compose 명령이 통째로 안 먹는다. 벗기는 것은 아래 3단계다.
🔴 설치 스크립트 여섯을 NAS 에 올린다 — 가장 먼저 사람
🔴 1단계부터 이것들을 부릅니다. 올리지 않고 시작하면 첫 명령이 「그런 파일이 없습니다」로 끝납니다.

1. 포털에 등록한다

클라이언트 시크릿을 만들고 해시를 뜬다 Claude
평문은 개발 PC 의 nas/env/board.env 에만 둔다(git 이 무시하는 파일). 포털에는 sha256 해시만 들어간다. 화면에도 채팅에도 평문을 찍지 않는다.
🔴 휴가 때와 다릅니다. 휴가는 이 일이 「0. 이미 끝난 것」에 있었지만 게시판은 아직 발급 전입니다.
운영 포털에 dss-board 를 넣는다 사람
NAS 에서 ssh dss-nas → sudo -i 한 뒤: 
sh /volume1/dss/setup/25-board-client.sh
이미 있으면 최신으로 맞춥니다(두 번 돌려도 안전). 봐 주실 것: 해시길이가 64 · 주소 셋이 전부 https://board.dss21.co.kr 로 시작 · available_roles 가 MEMBER · ADMIN · 아이콘 글자수 1 · 코드포인트 1FAA7
🔴 해시가 비어 있으면 스크립트가 아무것도 바꾸지 않고 멈춥니다. 시크릿을 아직 발급하기 전이라 그렇습니다(위 1-①). Claude 가 해시(64자)를 드리면 스크립트의 HASH= 줄을 채운 판을 다시 올리거나, 해시만 /volume1/dss/setup/incoming/board-client-hash.txt 로 올리면 됩니다. 평문 시크릿은 어디에도 적지 않습니다.
⚠️ requires_grant 가 f 입니다 — 전 직원이 바로 봅니다. PO 때처럼 명단을 따로 넣을 일이 없습니다(개선요청 · 휴가와 같습니다).
속에서 도는 것 — 포털 이미지에는 tsx 가 없어 등록 명령을 쓸 수 없습니다. 그래서 SQL 입니다:
insert into clients (
  client_id, name, description,
  client_secret_hash, redirect_uris,
  launcher_url, launcher_icon, sort_order,
  requires_grant, is_active,
  available_roles, backchannel_logout_uri
) values (
  'dss-board',
  'DSS 사내 게시판',
  '공지 · 자료 · 자유게시판',
  '<sha256 해시 64자>',
  array['https://board.dss21.co.kr/api/auth/callback'],
  'https://board.dss21.co.kr/',
  chr(129703),
  40,
  false,
  true,
  array['MEMBER','ADMIN'],
  'https://board.dss21.co.kr/api/auth/backchannel-logout'
)
on conflict (client_id) do update set ...;
🔴 아이콘을 셸에 글자로 적지 않습니다. 타일 그림은 U+1FAA7 인데, 그 글자를 스크립트에 그대로 적으면 DSM 터미널과 전송 과정에서 깨집니다 — 바이트가 바뀌어도 오류가 안 나고 포털 타일에 네모가 뜨고서야 압니다. 그래서 SQL 쪽에서 코드포인트로 만듭니다: chr(129703) = 16진 1FAA7. 넣은 뒤 스크립트가 to_hex(ascii(launcher_icon)) 로 코드값을 되읽어 보여 줍니다 — 눈이 아니라 코드로 확인하세요.
sort_order 40 은 잠정입니다 — 스크립트가 먼저 지금 목록을 찍어 보여 주니 그것을 보고 정합니다(휴가가 30 입니다).

2. DB 를 만들고 비밀번호를 한자리에서 정한다

🔴 같은 값이 세 곳에 들어갑니다. 한 번에 하는 이유입니다.
① NAS 의 DB 롤 dss_board_app ② .env.nas 의 BOARD_APP_PASSWORD ③ compose 가 그 값으로 DATABASE_URL 을 조립
한 글자라도 다르면 앱 로그에 password authentication failed 가 찍힙니다.
🔵 그래서 사람이 값을 정하지 않습니다. 25-board-pw.sh 가 무작위로 만들어 ①과 ②에 한꺼번에 넣고, 마지막에 그 값으로 실제로 붙어 봅니다. 2026-09-29 에 사람이 정한 값에 ? 가 들어가 DATABASE_URL 이 통째로 깨진 적이 있습니다(? 는 URL 에서 쿼리 시작 표시입니다).
DB dss_board 와 롤 dss_board_app 을 만든다 사람
🔴 새 DB 컨테이너를 만들지 않습니다. 이미 도는 dss-pg-app 안에 만듭니다 (개선요청 · 휴가와 같습니다). 두 번 돌려도 안전합니다 — 이미 있으면 건너뜁니다. 
sh /volume1/dss/setup/25-board-db.sh
🔴 인코딩·정렬을 다른 DB 와 같게 맞춥니다. 다르면 글 목록 차례가 사이트마다 달라집니다. 휴가를 만든 13-leave-db.sh 가 쓴 값 그대로입니다: 
CREATE ROLE dss_board_app LOGIN;

CREATE DATABASE dss_board
  OWNER dss_board_app
  ENCODING 'UTF8'
  LOCALE_PROVIDER icu ICU_LOCALE 'ko-KR'
  LOCALE 'C.UTF-8'
  TEMPLATE template0;

REVOKE CONNECT ON DATABASE dss_board FROM PUBLIC;
GRANT  CONNECT ON DATABASE dss_board TO dss_board_app;
스크립트가 마지막에 dss_as · dss_meters · dss_improvements · dss_leave 와 나란히 찍어 줍니다. 주인과 정렬 칸이 같은 줄이어야 합니다.
비밀번호를 한자리에서 정한다 사람
🔴 사람이 값을 정하지 않습니다. 스크립트가 영문·숫자 32글자를 무작위로 만들어 롤과 .env.nas 두 곳에 같은 값을 넣고, URL 로 조립해도 멀쩡한지 보고, 마지막에 TCP 로 실제로 붙어 봅니다. 
sh /volume1/dss/setup/25-board-pw.sh
🔴 값은 화면에 한 글자도 안 찍힙니다. .env.nas(root 600)에만 남습니다. 사람이 이 값을 칠 일은 없습니다 — compose 가 읽어 씁니다.
⚠️ 확인을 docker exec … psql 로만 하면 유닉스 소켓으로 붙습니다. 소켓은 보통 trust 라 비밀번호가 없어도 통과합니다 — 그래서 스크립트는 앱이 쓰는 길과 같게 -h 127.0.0.1(TCP)로 붙어 봅니다.
1·2단계가 되어 있는지 확인한다 사람
「했다」가 아니라 「되어 있다」를 봅니다. 읽기만 합니다 (딱 하나 — 첨부 폴더에 파일을 하나 만들었다 바로 지웁니다). 
sh /volume1/dss/setup/25-board-check.sh
보는 것 여섯: .env.nas 의 줄 · DB 와 롤과 주인 · 롤 비밀번호 · TCP 로 실제 접속 · 포털 등록(아이콘 코드포인트까지) · 첨부 폴더 권한. 전부 ✓ 면 3단계로 갑니다.
⚠️ 첨부 폴더는 4단계에서 만들어집니다. 그 전에 돌리면 폴더 항목만 ✗ 가 나오는 것이 정상입니다 — 4단계 뒤에 한 번 더 돌려 보세요.

3. 설정 파일을 만든다

board.env 를 완성한다 Claude
본은 dss-board/.env.example 입니다. 🔴 nas/env/ 에는 예시 파일을 두지 않습니다(nas/env/README.md 의 규칙 — 사본을 두면 언젠가 한쪽만 고쳐져 갈라집니다). 그래서 들어갈 내용을 여기 적어 둡니다. 이 표 하나로 파일을 만들 수 있습니다.
채울 일곱 줄 — 이것 말고는 아무것도 넣지 않습니다
이름값왜
OIDC_ISSUERhttps://login.dss21.co.kr 🔴 끝에 슬래시를 붙이지 않습니다. ID 토큰의 iss 와 글자 단위로 대조합니다
OIDC_CLIENT_IDdss-board포털 clients.client_id 와 같은 값
OIDC_CLIENT_SECRET포털이 발급한 평문 🔴 여기에만 적습니다. 포털에는 sha256 해시만 들어갑니다. NEXT_PUBLIC_ 을 붙이지 않습니다(브라우저로 새어나갑니다)
OIDC_REDIRECT_URIhttps://board.dss21.co.kr/api/auth/callback 🔴 다른 넷과 경로가 다릅니다 — /api/auth/sso/callback 이 아닙니다
AUTH_STATE_SECRET새로 만든 임의 문자열 🔴 운영용으로 새로 만듭니다 — 개발과 운영이 같은 비밀을 쓰지 않습니다.
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
SESSION_COOKIE_SECUREtrue 운영은 https 입니다. 반대로 http 에서 켜면 쿠키가 저장되지 않아 로그인이 조용히 실패합니다
SESSION_HOURS12 포털 SSO 세션의 절대 만료 12시간을 넘기지 않습니다. 넘겨 적으면 앱이 12로 깎습니다
🔴 .env.example 에서 빼고 오는 다섯 — 하나라도 들어가면 안 됩니다
이름왜 빼나
DATABASE_URLcompose 가 .env.nas 의 BOARD_APP_PASSWORD 로 조립해 넘깁니다
STORAGE_ROOTcompose 가 /data/uploads 로 넘깁니다 (볼륨과 짝이라 한 파일에 둡니다)
PORT이미지가 ENV PORT=3400 으로 들고 있습니다
TZcompose 가 Asia/Seoul 로 넘깁니다
SEED_DEV_ENABLED🔴 개발용 가짜 글을 넣는 울타리입니다. 없으면 꺼진 것이고, 운영 DB 를 가리킨 채 켜져 있으면 가짜 글이 들어갑니다
같은 값이 두 곳에 생기면 언젠가 한쪽만 바뀝니다 — 그때 앱은 오류 없이 다른 DB 를 보거나 엉뚱한 자리에 사진을 쌓습니다.
⚠️ 값에 따옴표를 두르지 않습니다. 줄 끝까지가 그대로 값입니다.
⚠️ 개발 PC 의 .env.local 은 OIDC_ISSUER · OIDC_REDIRECT_URI 가 auto 입니다. 운영은 다릅니다 — 컨테이너 안에서 auto 는 도커가 준 주소(172.x)를 집습니다.
compose 의 주석 둘을 벗긴다 Claude
app-board 와 tools-board. 🔴 함께 벗깁니다 — 하나만 벗기면 또 깨집니다. 벗기는 법은 그 자리 주석에 적혀 있습니다: 맨 앞 두 칸 뒤에 붙은 # 와 빈칸 하나만 지웁니다.
⚠️ tools-board 는 profiles: [tools] 라 평소에 뜨지 않지만 똑같이 막습니다 — compose 는 파일을 읽을 때 모든 서비스의 env_file 을 확인합니다.
🔴 db-app 에는 더할 줄이 없습니다. 개선요청은 세 자리를 함께 벗겼지만, 게시판은 롤과 DB 를 2단계에서 손으로 만들기 때문입니다(휴가와 같습니다). 거기에 줄을 더하면 db-app 의 설정 지문이 바뀌어, 인자 없는 up -d 가 DB 컨테이너를 다시 만듭니다.
야간 백업에 dss_board 와 board-uploads 를 더한다 Claude
🔴 개선요청이 이것 때문에 11일간 백업되지 않았습니다. 저장소에는 더해 놓고 NAS 에 그 파일을 안 올렸습니다. 고치는 것과 올리는 것은 다른 일입니다 — 아래 4단계에서 올린 것까지 확인합니다.
고칠 곳은 nas/jobs/backup-nightly.sh 의 두 줄입니다 — DB 목록에 dump dss-pg-app dss_board_app dss_board, 폴더 목록에 board-uploads. 그 파일은 이름을 박아 두고 있어서, 손대지 않으면 새 DB 도 올린 사진도 한 번도 백업되지 않습니다.
✅ 2026-10-13 에 더했습니다. 🔵 기존 다섯 DB · 네 폴더는 한 글자도 건드리지 않았습니다 — 더하기만 했습니다(git diff 의 지운 줄 0). 첨부 폴더는 이미 여섯 달 돌고 있는 for 줄에 이름을 끼워 넣지 않고 바로 아래에 따로 돌립니다. 하는 일은 글자 그대로 같습니다.

⚠️ tar 가 이미지의 1/4 쯤인 것은 정상입니다. 398MB 이미지가 92MB tar 입니다 — 「빌드가 잘못됐나」로 의심할 일이 아닙니다.
파일 다섯을 올린다 사람
🔴 scp 에 -O 를 붙입니다 — 없으면 DSM 에 sftp 가 없어 실패합니다.
🔵 스크립트 여섯은 1단계 앞에서 이미 올렸습니다(위 0-④). 
cd C:\Users\희만\Desktop\Development
scp -O dss-board-0.1.tar      dss-nas:/volume1/dss/images/
scp -O dss-board-tools-1.tar  dss-nas:/volume1/dss/images/
scp -O dss-deploy\nas\env\board.env dss-nas:/volume1/dss/setup/incoming/
scp -O dss-deploy\nas\docker-compose.nas.yml dss-nas:/volume1/dss/setup/incoming/
scp -O dss-deploy\nas\jobs\backup-nightly.sh dss-nas:/volume1/dss/setup/incoming/
올린 뒤 md5 를 맞춰 보고드립니다. 하나라도 다르면 멈춥니다.
제자리로 옮기고 첨부 폴더까지 만든다 사람
🔴 순서가 있습니다 — board.env 가 먼저입니다. 그것 없이 compose 의 app-board 를 켜 둔 판을 올리면 그 순간부터 docker compose 명령이 통째로 안 먹습니다. 앱을 멈춘 뒤에 그걸 알게 되면 다시 띄우지 못합니다. 스크립트가 그 차례를 지킵니다. 
sh /volume1/dss/setup/25-board-place.sh
하는 일 아홉: 올라온 것 확인 → board.env 를 먼저 (/volume1/dss/deploy/env/ · root 600) → 야간 백업 (/volume1/dss/jobs/ · root 700 · 문법까지 봅니다) → compose(문법을 먼저 보고 옮깁니다 · 644) → 첨부 폴더 만들기·ACL 걷기·권한 → 쓰기 시험 → 제자리 재확인 → 서비스 목록 → incoming 비우기.
⚠️ board.env 와 compose 는 md5 를 대조하지 않습니다 — 그 둘은 저장소에 없거나(비밀값) 주석을 벗긴 판이라 미리 잴 수 없었습니다. 스크립트가 받은 값을 찍어 주고 「대조하지 않았다」고 크게 말합니다. 제가 올리면서 잰 값과 눈으로 맞춰 주세요. 야간 백업은 대조합니다.
옛 파일은 지우지 않고 사본을 남깁니다 — backups/docker-compose.nas.yml.<시각> · jobs/backup-nightly.sh.bak-<시각>.
첨부 폴더가 제대로 됐는지 본다 (위 스크립트의 5·6번) 사람
🔴 컨테이너는 node(uid 1000)로 돕니다. dss 공유폴더에는 시놀로지 ACL(administrators 만 허용)이 걸려 있는데, uid 1000 은 DSM 계정이 아니라 ACL 로는 권한을 줄 수 없습니다. 그래서 이 폴더만 ACL 을 걷고 리눅스 권한으로 줍니다 — 01-prepare.sh 가 as-attachments · meters-files 에 한 것과 같은 방식이고, 개선요청의 improvements-uploads 도 같습니다.
속에서 도는 것 — 네 줄입니다(별도 명령이 아니라 위 스크립트 안입니다):
mkdir -p /volume1/dss/board-uploads
find /volume1/dss/board-uploads -exec /usr/syno/bin/synoacltool -del {} \; >/dev/null 2>&1
chown -R 1000:1000 /volume1/dss/board-uploads
chmod 750 /volume1/dss/board-uploads
봐 주실 것 — stat -c '%U:%G %a' 가 1000:1000 750 (이름이 없으면 숫자로 보입니다) · ACL 항목이 0개 · PROBE WRITE_OK · 시험 파일이 남지 않았다.
⚠️ 「있는가」가 아니라 「쓸 수 있는가」를 봅니다. 스크립트가 임시 컨테이너를 -u 1000:1000 으로 띄워 이 폴더에 실제로 파일을 만들었다 지웁니다. 권한 함정은 배포할 때 안 보이고 사람이 사진을 붙일 때 처음 드러납니다.
🔵 더 보고 싶으면 2단계의 확인 스크립트를 한 번 더 돌리세요 — 이번에는 폴더 항목까지 ✓ 가 됩니다. 
sh /volume1/dss/setup/25-board-check.sh
야간 백업이 게시판을 포함하는지 확인한다 사람 
bash /volume1/dss/jobs/backup-nightly.sh
dss_board 줄이 ✓ 로 더 나와야 합니다 (DB 여섯) · 폴더 목록에 board-uploads.
🔴 이 백업이 아래 첫 기동의 되돌릴 자리입니다.

6. 띄운다

🔴 여기부터가 진짜 설치입니다. 앞의 것이 하나라도 안 끝났으면 넘어오지 마세요.
다른 여섯 사이트는 멈추지 않습니다 — 새 서비스를 하나 더 띄우는 것뿐입니다 (up -d --no-deps app-board).
읽기만 — 어긋난 곳이 없는지 사람 
bash /volume1/dss/setup/25-deploy.sh
인자 없이 돌리면 아무것도 안 바꿉니다. 이미지 지문 · board.env · compose 의 주석이 벗겨졌는지 · DB 와 롤 · 첨부 폴더 권한 · 백업 · 주소를 봅니다. 실패 0 이어야 다음으로 갑니다.
이미지 둘을 싣는다 (앱 안 멈춤) 사람 
bash /volume1/dss/setup/25-deploy.sh --preload
md5 를 먼저 맞추고(어긋나면 안 싣습니다), 실은 뒤 지문을 대조하고, 도구 이미지 안의 마이그레이션이 1개인지 셉니다 (0000_blue_taskmaster.sql 하나가 표 일곱을 전부 만듭니다).
🔴 표를 만든다 — 앱보다 먼저 사람
🔴 표 일곱이 서야 첫 화면이 뜹니다. 없으면 첫 화면이 42P01 (relation "web_posts" does not exist) 로 죽습니다. DB 가 먼저입니다. 
bash /volume1/dss/setup/25-deploy.sh --init
속에서 도는 것:
cd /volume1/dss/deploy
/usr/local/bin/docker compose -f docker-compose.nas.yml \
  --env-file .env.nas --profile tools \
  run --rm tools-board npm run db:migrate
봐 주실 것 — 끝난 뒤 표가 일곱입니다: web_users · web_sessions · web_posts · web_post_files · web_post_images · web_post_views · web_audit_logs. 스크립트가 SQL 로 세어 찍습니다 — 「돌았다」가 아니라 「섰다」를 봅니다.
🔵 휴가의 seed:ranks 같은 채워 넣기는 없습니다. 게시판은 빈 표로 시작하고, 첫 사람이 로그인하는 순간 web_users 에 행이 생깁니다.
앱을 띄운다 사람 
bash /volume1/dss/setup/25-deploy.sh --go
app-board 하나를 띄우고 응답을 기다립니다. 다른 여섯은 그대로 돕니다 — --no-deps 라 dss-pg-app 도 안 건드립니다.
🔴 첫 관리자를 지정한다 — 길이 둘 사람
🔴 먼저 그 사람이 한 번 로그인해야 합니다. 로그인해야 web_users 에 행이 생기고, 그 전에는 두 길 다 「해당하는 계정이 없습니다」로 끝납니다. 처음 들어온 사람은 모두 MEMBER 입니다.
① 평소 길 — 포털 관리 화면
https://login.dss21.co.kr → 관리 → 그 직원 → 「시스템 접근·역할」 → DSS 사내 게시판 의 역할을 ADMIN 으로.
🔴 그 사람이 로그아웃했다 다시 로그인해야 반영됩니다. 역할은 로그인할 때 ID 토큰에 실려 옵니다 — 켜 둔 창에서는 안 바뀝니다.
🔵 이 사이트는 requires_grant=false 라 부여 행이 없는 사람이 정상입니다. ADMIN 을 주면 그때 행이 생기고, 그 뒤로는 로그인마다 그 값이 실려 옵니다.
② 비상구 — 포털이 막혔을 때
cd /volume1/dss/deploy
/usr/local/bin/docker compose -f docker-compose.nas.yml \
  --env-file .env.nas --profile tools \
  run --rm tools-board npm run make:admin -- "홍길동"
⚠️ 여기서 올린 역할은 영구적이지 않습니다. 포털이 그 사람에게 다른 역할을 실어 보내면 다음 로그인에 덮입니다. 오래 갈 변경은 ①에서 해야 합니다.
⚠️ 같은 이름이 둘이면 스크립트가 auth_sub 목록을 보여 주고 멈춥니다 — 그때는 이름 대신 그 UUID 를 넣습니다.

7. 눈으로 확인한다

🔴 검사가 통과해도 화면에서 잡히는 것이 있습니다. 휴가 설치하던 날 오전 배포는 통과 103 · 실패 0 이었는데, 알림 링크가 닿을 수 없는 주소로 나가는 것을 사람이 화면에서 찾았습니다.
로그인이 되는가 사람
https://board.dss21.co.kr 에 들어가 포털을 거쳐 로그인. 인증서 경고가 없어야 합니다(있으면 5단계 ③ 을 다시).
🔴 안 되면 거의 언제나 주소 넷 중 하나가 어긋난 것입니다(이 표 맨 위 상자). 앱 로그에 redirect_uri 가 그대로 찍히니 포털 등록값과 글자로 견줍니다. 172. 로 시작하면 board.env 에 auto 가 남은 것입니다.
게시판에서 로그아웃하면 포털까지 가는가 사람
게시판에서 로그아웃 → 포털로 넘어가 포털 세션도 끝나야 합니다. 다시 https://board.dss21.co.kr 를 열었을 때 로그인 화면이 떠야 합니다.
🔴 포털에서 로그아웃하면 게시판도 끊기는가 사람
백채널 로그아웃이 도는지를 보는 유일한 길입니다. 두 탭을 열어 둡니다 — 한쪽은 login.dss21.co.kr, 다른 쪽은 게시판. 포털에서 로그아웃한 뒤 게시판 탭을 새로고침 하면 로그인 화면이 떠야 합니다.
안 끊기면 포털의 backchannel_logout_uri 가 틀린 것입니다 — https://board.dss21.co.kr/api/auth/backchannel-logout 와 글자로 견줍니다. 🔵 오류가 안 납니다. 그래서 눈으로만 잡힙니다.
머리말 메뉴바가 보이는가 사람
화면 맨 위 메뉴바에 다른 사내 사이트들이 보여야 합니다. 목록은 포털이 ID 토큰에 실어 보냅니다.
⚠️ 안 보이면 고장이 아니라 재로그인 문제일 수 있습니다. 한 번 로그아웃하고 다시. 서버를 껐다 켠 뒤에 쿠키가 안 맞아 그렇게 보인 적이 있습니다 — 코드를 의심하다 하루치를 버릴 뻔했습니다.
🔴 글에 사진을 붙여 본다 — 이 설치의 핵심 사람
🔴 권한 함정은 여기서만 드러납니다. 컨테이너는 uid 1000 으로 도는데 첨부 폴더 주인이 다르면, 배포 검사는 전부 통과하고 사람이 사진을 붙이는 순간 처음 깨집니다.
글 하나를 쓰고 사진을 붙여 저장 → 목록에서 다시 열어 사진이 보이는지 → 첨부 파일도 하나 붙여 내려받아지는지.
그리고 NAS 폴더에 실제로 바이트가 놓였는지를 봅니다:
find /volume1/dss/board-uploads -type f | tail -5
🔴 화면에 사진이 보이는데 여기가 비어 있으면 볼륨이 안 붙은 것입니다 — 그 바이트는 컨테이너 안에 있고, 다음 배포에서 컨테이너를 새로 만드는 순간 전부 사라집니다. 그때는 화면에는 첨부가 있는데 바이트만 없는 상태가 됩니다. 여기서 멈추고 알려 주세요.
포털 타일에 🪧 게시판이 보이는가 사람
https://login.dss21.co.kr. requires_grant 가 꺼져 있어 전 직원에게 바로 보여야 합니다.
⚠️ 그림이 네모로 보이면 브라우저에 그 글꼴이 없는 것일 수도, 값이 깨진 것일 수도 있습니다. 가르는 길은 코드값입니다 — sh /volume1/dss/setup/25-board-check.sh 의 4번이 글자수 1 · 코드 1FAA7 을 찍어 줍니다.
관리 화면이 열리는가 사람
6-⑤ 에서 ADMIN 을 받은 분으로 로그인해 /admin/users 가 열리는지. 일반 직원으로는 안 열려야 합니다 — 둘 다 봅니다 (「맞으면 되나」와 「틀리면 안 되나」).

8. 마무리

야간 백업에 게시판이 들어갔는지 다음 날 아침 다시 본다 사람 
ls -lt /volume1/dss/backups/db/ | head -8
🔴 손으로 한 번 돌린 것과 스케줄러가 도는 것은 다릅니다. dss_board 덤프가 저절로 생기는지가 진짜 확인입니다. 개선요청이 「더했다」고 문서에 적힌 채 11일간 백업되지 않았습니다.
🔴 메모리를 실측해 예산표를 다시 적는다 사람 Claude 
/usr/local/bin/docker stats --no-stream
🔴 일곱째 사이트입니다. compose 맨 아래 「메모리 예산」은 여섯까지 적혀 있고, 그 표가 「일곱째를 더할 때는 이 표를 믿지 말고 그때 실측하라」고 적어 두었습니다. 상한 합계가 4,096M → 4,480M 이 되어 여유 칸이 1GB 아래로 내려갑니다.
🔵 상한이지 예약이 아닙니다. Next.js standalone 한 채가 평시 100~150MB 입니다. 그래도 잰 값을 적어 둡니다.
문서를 갱신한다 Claude
배포 지도(dss-deploy/README.md)의 운영 주소 표에서 게시판 줄의 「설치 전」 표시를 떼고, HANDOFF · 진행현황판을 고칩니다. 커밋하고 올립니다.

되돌리기

무엇이 잘못됐나어떻게
docker compose 가 통째로 안 먹는다 🔴 가장 나쁜 경우입니다. 거의 언제나 env/board.env 가 제자리에 없는데 compose 의 주석을 벗긴 판을 올린 것입니다. /volume1/dss/deploy/env/board.env 가 있는지 보고, 없으면 compose 를 옛 판으로 되돌립니다 — cp /volume1/dss/backups/docker-compose.nas.yml.<날짜> /volume1/dss/deploy/docker-compose.nas.yml. 25-board-place.sh 가 바꾸기 전 사본을 거기 남깁니다.

이 저장소가 배운 것 — 이 설치에 그대로 쓰입니다

「있는가」가 아니라 「제 일을 하는가」를 봅니다. 같은 함정에 여러 번 걸렸습니다.
  • 폴더는 주인이 맞는데 ACL 이 막아 컨테이너가 못 읽었다
  • 이미지는 이름표가 맞는데 속이 8일 전 판이었다
  • 통로는 응답이 오는데 내주는 주소가 컨테이너 것(172.x)이었다
  • 백업은 문서에 「더했다」고 적혀 있는데 NAS 에 안 올렸다(11일간)
넷 다 오류가 안 났습니다. 그래서 이 점검표는 결과를 봅니다 — 폴더는 컨테이너 안에서 열고, 이미지는 안의 파일을 세고, 주소는 받아 보고, 표는 SQL 로 세고, 백업은 다음 날 아침에 다시 봅니다.
🔴 DSM 터미널은 긴 명령을 잘라 먹습니다. 하루에 네 번 깨진 적이 있습니다. 위의 긴 docker compose 줄들은 「속에서 도는 것」으로만 적어 두었고, 손으로 치실 것은 전부 bash /volume1/dss/setup/25-*.sh 꼴의 한 줄입니다. 스크립트를 올린 뒤에는 md5 를 맞추고 들어갑니다 — 두 값이 다르면 실행하지 말고 다시 올립니다.
