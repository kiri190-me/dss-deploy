## 0. 06(개선요청)과 무엇이 다른가

| | 개선요청 첫 배포 | **PO 첫 배포** |
|---|---|---|
| DB | 롤·DB 를 손으로 만든다 | 🔴 **없다** — A/S 의 `dss_as` 를 그대로 본다 |
| DB 비밀번호 | `.env.nas` 에 한 줄 더한다 | 🔴 **없다** — `AS_APP_PASSWORD` 를 그대로 쓴다 |
| 파일 볼륨 | 새 폴더를 만들고 권한을 준다 | 🔴 **없다** — A/S 의 `as-attachments` 를 **함께 쓴다** |
| 양식 | 없다 | A/S 의 `as-templates` 를 **함께 읽는다**(읽기 전용) |
| 공유폴더 | 없다 | 🔴 A/S 와 **같은 bind** + `group_add: ["100"]` |
| 포털 | clients 에 줄을 넣고 시크릿 발급 | 같다 |
| 주소 | DNS 한 줄 + 프록시 규칙 하나 | 같다 |
| 설정 파일 | `env/improvements.env` | `env/po.env` |
| 이미지 | 이미 Dockerfile 이 있었다 | 🔴 **없다 — 먼저 만든다** (1절) |
| 도구 이미지 | 있다(마이그레이션) | 🔴 **없다** — PO 에는 마이그레이션도 야간 작업도 없다 |

**왜 DB 를 안 나누나** — 설계 결정이다(`PO_DOMESTIC_SPLIT_DESIGN.md` B-2 · D절).
내자 목록 화면 하나가 `repair_cases` · `products` · `customers` · `quotes` 를 한
질의에 LEFT JOIN 하고, 수리 건을 지우면 `ON DELETE SET NULL` 이 연결을 자동으로
푼다. 나누면 그 둘이 깨진다. 그래서 `dss-po` 에는 마이그레이션도
`drizzle.config.ts` 도 없다 — **스키마의 주인은 A/S 하나뿐이다.**

**왜 첨부 폴더를 함께 쓰나** — 두 사이트가 같은 `attachments` 표를 본다. 표에는
파일의 **상대 경로**만 있다. 폴더를 나누면 A/S 에서 붙인 파일을 PO 가 못 찾는다
(반대도 같다). **같은 폴더를 붙이는 것이 유일하게 맞는 답이다.**

## 1. 🔴 먼저 할 일 — `dss-po` 에 이미지 굽는 파일이 없다

```

dss-auth/Dockerfile               94줄   있다

dss-po/.dockerignore                     🔴 없다
```

**이것은 이 문서의 일이 아니라 `dss-po` 저장소의 일이다.** 만들 때 지킬 것:

- **본보기는 `dss-improvements/Dockerfile`** 이다 — 넷 중 가장 최근이고 `output:
  "standalone"` 을 쓰는 모양이 PO 와 같다(`dss-po/next.config.ts` 도 standalone).
- 🔴 **서브모듈 둘이 이미지 안에 들어가야 한다** — `vendor/dss-ui`(메뉴바 · 알림 종)와
  `vendor/dss-core`(공용 스키마 · 공용 화면). 작업 트리에 실제 파일이 있으므로
  `COPY . .` 로 함께 들어가지만, **`.dockerignore` 가 `vendor` 를 막으면 빌드가 크게
  실패한다.** 비어 있으면 조용히 옛 코드가 쓰이는 것이 아니라 **빌드가 죽는다** —
  그 점은 다행이다.
- **빌드용 가짜 `DATABASE_URL`** 이 필요하다. `next build` 가 서버 모듈을 실제로
  불러오는데 `src/lib/env.ts` 의 `required()` 가 값이 없으면 던진다. 개선요청
  Dockerfile 의 그 주석과 값을 그대로 쓴다.
- 🔴 **양식 경로 다섯은 빌드에 필요 없다.** `env.ts` 가 전부 getter 라 쓰는 시점에만
  본다. 빌드 때 값을 넣지 마라 — 넣으면 이미지에 사내 경로가 박힌다.
- **도구(tools) 스테이지는 만들지 않는다.** PO 에는 NAS 에서 돌릴 스크립트가 없다
  (마이그레이션 · 야간 완전삭제는 A/S 의 `dss-as-tools` 가 계속 맡는다).
- 굽는 절차는 `runbook/02-이미지-빌드.md` 와 같다.

| 메모리 | **640M** — A/S 와 같게 | compose |
| 역할 | A/S 와 같은 표를 본다 | 권한은 A/S 의 「역할별 접근 권한」이 정한다 |

⚠️ **`group_add: ["100"]` 을 빠뜨리지 마라.** 견적서 공유폴더는 `/volume1/dss` 와 달리
Synology ACL 이 **사람 이름으로** 허용하는 곳이다. `ls` 에 777 로 보여도 판정은 ACL 이
하고, 컨테이너의 `node`(uid 1000)는 DSM 사용자가 아니라 그 목록에 없다 — 그대로 두면
**Permission denied** 다. A/S 서비스가 같은 까닭으로 이미 그렇게 하고 있다
(`app-as` 의 그 주석, 2026-09-16 실측).

⚠️ **ACL 을 걷지 마라.** `/volume1/dss` 에 하는 것처럼 여기서 ACL 을 걷으면
**직원의 탐색기 접근이 끊긴다.** 이 폴더는 직원이 20년째 쓰는 실제 서류함이다.

## 3. 🔴 사람이 손으로 하는 일 — 이 순서대로

ㄱ~ㅂ 을 다 한 뒤에 4절(이미지)로 간다. **ㅂ 은 ㅁ 뒤여야 한다** — 설정 파일이
NAS 에 없는데 compose 에 서비스를 켜 두면 `docker compose` 명령이 **통째로** 안 먹는다.

### ㄱ. 운영 백업을 먼저 뜬다

🔴 **이 배포는 A/S 의 DB 를 건드리는 배포다.** PO 가 같은 표에 쓰기 때문이다.
PO 자체는 마이그레이션이 없지만, 같은 창구에서 도는 **연락서 일괄 이식**이 실제
자료를 넣는다. 배포 전에 운영 DB 백업을 뜬다 — 절차는 `runbook/07` 의 그 절.

### ㄴ. 🔴 DB — **할 일이 없다**

A/S 와 같은 `dss_as` 를 같은 롤 `dss_app` 으로 본다. 롤도 DB 도 이미 있다.
**`nas/init/app/01-roles.sh` 를 고치지 마라. `.env.nas` 에 줄을 더하지 마라.**

> 확인만 한다 — 06 의 ㄴ 을 습관으로 따라 하다가 `dss_po` 라는 빈 DB 를 만들면,
> 앱은 그쪽을 보고 표가 없어 뜨자마자 죽는다. **compose 의 `DATABASE_URL` 이
> A/S 줄과 글자 하나까지 같은지**가 유일한 확인이다.

### ㄷ. 🔴 파일 볼륨 — **할 일이 없다**

`/volume1/dss/as-attachments` 를 A/S 와 **함께** 쓴다. 폴더도 권한도 이미 있다.
**새 폴더를 만들지 마라** — 만들면 A/S 에서 붙인 파일을 PO 가 못 찾는다.

### ㄹ. 포털(dss-auth)에 클라이언트를 등록한다

06 의 같은 절과 **절차가 같다.** 다른 값만 적는다.

| | 값 |
|---|---|
| `client_id` | `dss-po` |
| 이름 | `PO / 내자` |
| `redirect_uri` | `https://po.dss21.co.kr/api/auth/sso/callback` |
| `launcher_url` | `https://po.dss21.co.kr` |
| 백채널 로그아웃 | `https://po.dss21.co.kr/api/auth/sso/backchannel-logout` |

발급한 시크릿은 **ㅁ 의 `po.env`** 에 들어간다. 여기서 한 번 보고 마는 값이다.

🔴 `launcher_url` 은 **포털 타일과 메뉴바 목록**이 읽는 값이다(`clients.launcher_url`).
이 줄이 없거나 틀리면 다른 사이트의 메뉴바에 **PO 가 안 뜬다.**

🔴 **누가 들어갈 수 있는지는 포털이 정하지 않는다.** 화면별 권한은 A/S 의
「사용자 관리 › 역할별 접근 권한」이 정하고, **두 시스템이 같은 설정을 본다.**
포털 등록은 「로그인이 되는가」까지다.

비워 두면 링크가 안 서고 인수번호가 **글자로만** 보인다 — 고장이 아니라 설계된
갈래다. 그래도 적는 편이 낫다.

올리는 법은 06 과 같다 — `setup/incoming/` 에 두고 사람이 `sudo` 로 옮긴 뒤
**root 600** 으로 만든다.

그리고 `nas/env/README.md` 의 표에 `po.env` 한 줄을 더한다.

### ㅂ. compose 에 서비스를 하나 더한다

`nas/docker-compose.nas.yml` 에 `app-po` 를 더한다. 🔴 **`app-as` 를 통째로
복사해 아래 여섯만 바꾸는 것이 가장 안전하다** — 볼륨 셋과 `group_add`,
`DATABASE_URL` 을 손으로 다시 쓰면 한 글자가 틀린다.

```yaml
  app-po:
    image: dss-po:0.1
    container_name: dss-po
    restart: unless-stopped
    logging: *logging
    networks: [dss-data, dss-edge]
    ports: ["127.0.0.1:13600:3600"]        # ← 바뀜
    # ⚠️ 견적서 공유폴더의 Synology ACL 때문이다. 까닭은 app-as 의 같은 줄 주석.
    group_add: ["100"]
    env_file:
      - ./env/po.env                        # ← 바뀜
    environment:
      TZ: Asia/Seoul
      # 🔴 A/S 와 **같은 DB · 같은 롤 · 같은 비밀번호**다. 새 값을 만들지 않는다.
      DATABASE_URL: postgresql://dss_app:${AS_APP_PASSWORD}@dss-pg-app:5432/dss_as
      # 🔴 A/S 와 **같은 폴더**다. 같은 attachments 표를 보므로 나누면 서로의 파일을 못 찾는다.
      UPLOADS_DIR: /data
      # 양식 다섯 — A/S 는 일곱을 쓰지만 이 사이트는 견적서 다섯만 쓴다.
      QUOTE_TEMPLATE_PATH: "/templates/내자견적서.xlsx"
      OH_QUOTE_TEMPLATE_PATH: "/templates/제너레이터 OH 견적서.xlsx"
      MATCHER_QUOTE_TEMPLATE_PATH: "/templates/매쳐 내자 견적서.xlsx"
      MATCHER_OH_QUOTE_TEMPLATE_PATH: "/templates/매쳐 OH 견적서.xlsx"
      CABLE_QUOTE_TEMPLATE_PATH: "/templates/케이블 견적서.xlsx"
    volumes:
      - /volume1/dss/as-attachments:/data           # 🔴 A/S 와 같은 폴더
      - /volume1/dss/as-templates:/templates:ro
      # 경로에 공백과 괄호가 있어 긴 문법으로 적는다 — 까닭은 app-as 의 같은 줄 주석.
      - type: bind
        source: "/volume1/3_견적-세금계산서-국내발주/4. DSS 내자견적서 (활용)"
        target: /quote-archive
    depends_on:
      db-app:
        condition: service_healthy
    deploy:
      resources:
        limits:
          memory: 640M                      # A/S 와 같게 — 엑셀 파싱에서 크게 튄다
```

🔴 **도구 서비스(`tools-po`)는 만들지 않는다.** PO 에는 NAS 에서 돌릴 스크립트가
없다. 마이그레이션과 야간 완전삭제는 **A/S 의 `tools-as` 가 계속 맡는다** —
그 야간 작업이 PO 의 휴지통도 함께 비운다(같은 표이기 때문이다). 🔴 **그것을
A/S 에서 걷어내면 PO 휴지통이 영영 안 비워진다.** 화면은 계속 「15일 뒤 자동
삭제」라고 말하면서.

## 5. 띄우고 확인한다

```bash
# (NAS)
cd /volume1/dss/deploy
sudo docker compose -f docker-compose.nas.yml up -d app-po
sudo docker compose -f docker-compose.nas.yml ps app-po
sudo docker compose -f docker-compose.nas.yml logs -f --tail=100 app-po
```

### 확인표 — 이 순서로 본다

| # | 무엇 | 어떻게 | 어긋나면 |
|---|---|---|---|
| 1 | 컨테이너가 살아 있다 | `ps` 에 `Up` | 로그를 본다. `required()` 가 던졌으면 `po.env` 의 빠진 이름이 그대로 찍힌다 |
| 2 | 로그인이 된다 | `https://po.dss21.co.kr` → 포털 → 돌아옴 | ㄹ 의 `redirect_uri` 가 **글자 단위로** 같은지 |
| 3 | 메뉴바에 다섯 사이트가 보인다 | 머리말 | 포털의 `launcher_url` |
| 4 | 🔴 **A/S 에서 만든 견적서가 보인다** | `/quotes` 목록 | **DB 가 다른 것을 보고 있다.** compose 의 `DATABASE_URL` |
| 5 | 🔴 **A/S 에서 붙인 파일이 열린다** | 견적서 → [내려받기] | **첨부 폴더가 다르다.** `UPLOADS_DIR` 볼륨 |
| 6 | 견적서 받기(엑셀)가 된다 | 목록 → [견적서 받기] | 양식 다섯의 이름·경로 |
| 7 | 미리보기가 그려진다 | 목록 → [미리보기 · PDF] | 같은 양식 |
| 8 | 🔴 **발행이 공유폴더에 파일을 놓는다** | 편집 → [견적서 받기](발행) → 탐색기에서 확인 | `group_add: ["100"]` · bind 경로 |
| 9 | [폴더 열기]가 탐색기를 연다 | 편집 → [폴더 열기] | 「꺼져 있습니다」면 `QUOTE_ARCHIVE_DIR`. 「도우미가 없다」면 그 PC 에 도우미 설치 |
| 10 | 내자 인수번호가 A/S 로 간다 | `/domestic-orders` → 인수번호 | 글자로만 보이면 `AS_APP_BASE_URL` |
| 11 | 결재가 돈다 | 견적서 → [결재] 탭 → 올리기 | 결재선은 **A/S 에서 설정**한다 |

🔴 **4번과 5번이 이 배포의 핵심이다.** 둘 중 하나라도 어긋나면 **DB 나 첨부 폴더를
잘못 붙인 것**이고, 그 상태로 사람이 쓰면 **자료가 두 곳으로 갈라진다.**
그때는 바로 `down` 하고 compose 를 고친다.

## 6. 되돌리기

PO 는 **없던 것이 생기는 배포**라 되돌리기가 쉽다.

```bash
sudo docker compose -f docker-compose.nas.yml down app-po
```

- 🔴 **DB 는 건드리지 않는다.** PO 는 스키마를 바꾸지 않았다(마이그레이션이 없다).
- 🔴 **첨부 폴더도 건드리지 않는다.** PO 가 올린 파일은 A/S 에서도 그대로 보인다 —
  같은 표 · 같은 폴더이기 때문이다. **지우지 마라.**
- A/S 는 그대로 돌고 있다. 사람은 A/S 의 견적서·내자로 계속 일할 수 있다
  (이번에 걷어내지 않기로 한 까닭이 이것이다).
- 프록시 규칙과 DNS 는 남겨 둬도 해가 없다(닿을 곳이 없으면 502 다).

## 7. 이 배포에 딸린 것 — 연락서 일괄 이식

🔴 **같은 창구에서 하되 같은 단계로 묶지 않는다**(2026-09-28 사용자 결정).

- **연락서를 먼저** 한다. A/S 의 `dss-as-tools` 이미지로 469장을 넣는 일이고,
  **실제 자료를 넣는다** — 되돌리기 도구가 함께 있다(`revert --batch`).
- 그것이 끝나고 **확인이 된 뒤에** PO 를 띄운다.
- 두 일은 서로를 기다리지 않는다. 연락서가 잘못돼도 PO 배포는 그대로 갈 수 있고,
  반대도 같다. **같은 날 하는 것뿐이다.**

자세한 것은 `RF_Service_System/2026-09-28-결정할것.html` 3번.

## 8. 아직 정해지지 않은 것

- **주소 이름** — 이 문서는 `po.dss21.co.kr` 로 적었다. `quotes.` 나 `order.` 가
  낫다면 3-ㄹ · 3-ㅅ · `po.env` 의 `SSO_REDIRECT_URI` **세 곳을 함께** 고친다.
- **A/S 쪽 견적서·내자를 언제 걷어내나** — 이번에는 안 한다. PO 가 운영에서 도는
  것을 보고 정한다. 그때 A/S 에 `PO_APP_BASE_URL` 이 필요해진다(결재 알림 링크가
  A/S 자기 `/quotes` 로 가고 있어서, 걷어내는 순간 404 가 된다).
- **이미지 판 번호** — `0.1` 로 적었다. 다른 넷의 관행과 맞추려면 첫 배포는 `0.1`,
  고칠 때마다 올린다.
