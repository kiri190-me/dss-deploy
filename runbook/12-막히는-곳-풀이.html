점검표(11)는 무엇을 할지를 적은 표입니다. 이 문서는 그중 막상 하려면 막히는 것을 단계로 풉니다. 제가 대신 할 수 있는 일에는 그대로 복사해서 저에게 주실 프롬프트를 붙였습니다.

제가 함 제가 파일을 고칩니다 · 직접 NAS·DSM·포털에서 사람이 합니다

🔴 이 문서를 쓰면서 점검표에 없던 단계를 하나 찾았습니다 — 5번입니다.
포털에 PO 를 등록해도 「누가 쓸 수 있는가」를 따로 넣지 않으면 아무도 못 들어갑니다. 개발 포털 실측: PO 에 권한이 있는 사람 1명, A/S 는 5명.

1업데이트 소식 — 「맨 앞에 더한다」가 무슨 뜻인가제가 함

업데이트 소식은 자동으로 만들어지지 않습니다. 파일 하나에 사람이 손으로 적는 목록입니다.

어디dss-auth/src/lib/release-notes.ts
무엇그 파일 안의 RELEASES 라는 목록. 목록의 맨 위가 화면의 맨 위입니다.
모양한 칸이 「배포 하나」이고, 그 안에 「달라진 것」이 여러 줄 들어갑니다.
지금 파일에 들어 있는 모양 — 이 꼴로 하나를 더합니다
export const RELEASES = [
  {                          ← 🔴 새 배포는 여기, 맨 앞에 들어갑니다
    system: "A/S 관리",       ← 어느 시스템
    version: "1.6",           ← 도커 이미지 태그와 같은 번호
    date: "2026-09-18",       ← 배포한 날
    title: "과거 인수품을 가져오면 …",   ← 한 줄 요약
    items: [
      { kind: "개선", text: "…" },      ← 추가 · 개선 · 고침 중 하나

]
⚠️ 왜 미리 안 넣어 두나 — 그 파일이 스스로 적어 두었습니다. 「미리 적어 두면 화면은 아직 돌지도 않는 판을 광고하게 된다」. 그래서 이미지를 굽는 날 넣습니다.
🤖 이럴 때 저에게 이렇게 말씀하세요
업데이트 소식 글을 넣어줘.
10-업데이트소식-초안.html 의 글 셋을 dss-auth 의 RELEASES 맨 앞에 넣고,
판 번호는 A/S 1.7 · PO 0.1 · 개선요청 0.1 · 포털 1.5 로,
날짜는 오늘로 해줘. 넣고 시험까지 돌려서 보여줘.

🔴 판 번호와 날짜는 실제로 굽는 값으로 바꿔 주세요. 그게 이 프롬프트에서 유일하게 사람이 정하는 부분입니다.

이번에 정할 것 — 포털을 1.5 로 올릴까

포털은 글 때문에 다시 굽습니다. 그러면 이미지가 바뀌므로 번호도 올리는 편이 맞습니다. 권장: 1.5 로 올리고 통합 로그인 항목도 한 줄 더합니다 — 「업데이트 소식에 PO / 내자와 개선요청의 소식도 함께 보입니다.」

3compose 고치기 — 네 군데, 그리고 NAS 로 옮기는 길제가 함

docker-compose.nas.yml 은 NAS 에서 무엇이 어떻게 도는지를 적은 설계도입니다.

#무엇왜
①app-as 의 태그를 dss-as:1.7 로A/S 앱을 새 것으로 바꾸려고
②app-auth 의 태그를 dss-auth:1.5 로소식 글이 포털에 있어서
③app-po 의 주석을 벗긴다지금은 줄 앞에 # 가 붙어 꺼져 있습니다
④tools-as 에 볼륨 둘 + group_add연락서 원본을 컨테이너가 봐야 해서

고친 파일이 NAS 로 가는 길직접

  1. 제가 개발 PC 의 dss-deploy/nas/docker-compose.nas.yml 을 고칩니다.
  2. 그 파일을 NAS 의 setup/incoming/docker-compose.nas.yml 에 올립니다 (File Station 으로 끌어다 놓으면 됩니다).
  3. 배포 스크립트가 바꾸기 전에 문법과 설정 파일 존재를 먼저 검사하고 갈아 끼웁니다. 옛 파일은 backups/ 에 남습니다.
⚠️ 스크립트를 안 쓰고 손으로 옮긴다면 옛 파일을 먼저 복사해 두고 deploy/docker-compose.nas.yml 에 sudo 로 옮깁니다(root:root 644).
🤖 프롬프트
compose 를 배포용으로 고쳐줘.
① app-as 태그를 dss-as:1.7 로 ② app-auth 를 dss-auth:1.5 로
③ app-po 주석 벗기고 ④ tools-as 에 연락서 볼륨 둘과 group_add 추가.
고친 뒤 문법 검사랑 서비스 목록까지 확인해서 보여줘.

4포털에 PO 등록 — 화면이 아니라 SQL 입니다직접

⚠️ 왜 화면이 아닌가 — 포털의 등록 명령은 tsx 로 도는 스크립트인데 NAS 의 포털 이미지에는 그것이 없습니다. A/S·계측기와 달리 포털에는 도구 이미지가 없습니다. 그래서 SQL 로 직접 넣습니다.

순서

  1. 개발 PC 에서 시크릿을 만들어 po.env 에 바로 적고, 해시만 화면에 찍습니다. 평문은 화면에 안 남깁니다.
  2. 그 해시를 들고 NAS 로 가서 SQL 을 한 번 돌립니다.
  3. 5번(권한 주기)으로 넘어갑니다. 🔴 여기서 끝이 아닙니다.
PowerShell (개발 PC · nas/env 폴더에서) — 시크릿을 파일에 적고 해시만 출력
cd "C:\Users\희만\Desktop\Development\dss-deploy\nas\env"
node -e "const c=require('crypto'),fs=require('fs');const s=c.randomBytes(32).toString('base64url');fs.appendFileSync('po.env','SSO_CLIENT_SECRET='+s+'\n');console.log(c.createHash('sha256').update(s,'utf8').digest('hex'))"

화면에 찍힌 긴 16진수 한 줄이 아래 SQL 의 client_secret_hash 자리에 들어갑니다.

✅ 등록할 값은 개발 포털에 이미 있는 것을 본으로 씁니다. 2026-09-28 실측 — dss-po · 아이콘 📋 · sort_order 15 · requires_grant true(A/S 와 같습니다).
🤖 프롬프트 — SQL 은 제가 만들어 드립니다
포털에 PO 를 등록할 SQL 을 만들어줘.
개발 포털의 dss-po 줄을 본보기로 하고, 주소는 po.dss21.co.kr 로.
client_secret_hash 는 <여기에 넣으세요> 로 비워 두고,
어디에 붙여넣는 명령인지도 같이 알려줘.

5🔴 권한 주기 — 이걸 안 하면 아무도 못 들어갑니다직접

🔴 점검표에 없던 단계입니다. PO 는 requires_grant = true 로 등록합니다 — 「명단에 있는 사람만 쓴다」는 뜻입니다. 등록만 하고 명단을 안 넣으면 포털 타일에도 안 보이고 로그인도 막힙니다.
설정뜻쓰는 곳
requires_grant = false포털에 로그인되는 모든 직원이 쓴다계측기 · 휴가 · 개선요청
requires_grant = true명단에 있는 사람만A/S · PO

개발 포털 실측 — A/S 는 5명 전원, PO 는 1명뿐입니다.

누구에게 줄까요직접

권장 — 지금 A/S 에서 견적서·내자를 쓰는 사람들입니다. 화면별 권한은 따로입니다 — 그건 A/S 의 「사용자 관리 › 역할별 접근 권한」이 정하고 두 시스템이 같은 설정을 봅니다. 포털 명단은 「PO 라는 사이트에 들어갈 수 있는가」까지입니다.

🤖 프롬프트
PO 접근 권한을 줄 SQL 을 만들어줘.
운영 포털에서 지금 A/S 를 쓸 수 있는 사람 전원에게 똑같이 주는 걸로.
먼저 「누가 받게 되는지」를 보는 조회부터 만들고,
실제로 넣는 SQL 은 그다음에 따로 줘.

🔴 먼저 보고 나중에 넣는 순서로 부탁하시는 게 안전합니다 — 누가 받는지 눈으로 보고 넣습니다.

6po.env — 19개 값이 어디서 오나제가 함

「19개를 채운다」가 막막한데, 실제로 사람이 정하는 것은 둘뿐입니다.

갈래어떤 것어떻게
🔴 만든다AUTH_SESSION_SECRET · SSO_TX_SECRET 사람이 만듭니다. 4번의 명령과 같은 방식. 🔴 A/S 와 다른 값
받는다SSO_CLIENT_SECRET4번에서 파일에 저절로 들어갑니다
베낀다QUOTE_ARCHIVE_UNC_ROOT · _ALT NAS 의 as.env 에서 그대로. 고쳐 쓰지 마세요
정해짐나머지 열넷양식 다섯 · 주소 넷 · true 같은 값들 — 제가 채워 드립니다
지운다DATABASE_URL · UPLOADS_DIR · PORT compose 와 이미지가 넘깁니다. 두 곳에 있으면 언젠가 한쪽만 바뀝니다
🤖 프롬프트
po.env 를 만들어줘. 정해진 값은 다 채우고,
사람이 넣어야 하는 자리는 <여기에 넣으세요> 로 비워 둬.

⚠️ 비밀값은 제가 만들지 않습니다. 만들어 드리면 그 값이 우리 대화에 남습니다. 자리만 비워 드리고, 만드는 명령을 알려 드립니다.

7「회차 번호를 받아 적는다」가 무슨 뜻인가직접

연락서 469장을 넣으면, 그 469장 전부에 같은 번호표가 붙습니다. 그것이 회차 번호입니다.

  • 어디에 나오나 — 넣는 명령이 맨 처음과 맨 끝에 찍습니다.
  • 왜 적나 — 뭔가 잘못됐을 때 그 번호 하나로 469장을 통째로 되돌립니다.
  • 안 적으면 — 되돌리려고 화면 기록을 뒤져야 합니다. 터미널을 닫았으면 더 어렵습니다.
🔴 종이에 적으세요. 터미널 창을 믿지 마세요. 「복사해 두기」도 중간에 다른 걸 복사하면 날아갑니다.
