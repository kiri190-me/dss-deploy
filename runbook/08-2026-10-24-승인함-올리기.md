# 통합 승인함을 NAS 에 올린다 (2026-10-24)

승인함(`dss-approvals`)은 **열째 사이트**이자 이 묶음의 마지막 조각이다. 서른다섯째
배포의 **②** 에 해당한다(① 은 네 시스템의 새 판 — `37-build.sh` · `37-deploy.sh`).

🔵 **① 이 먼저 돌아도 된다.** 승인함이 없어도 결재 메일은 나간다 — 메일에서 **주소 줄만**
빠진다(`dss-auth/src/lib/approvals/inbox-url.ts` 가 그렇게 지어져 있다). 그래서 이 문서의
일은 급하지 않다.

---

## 🔴 0. 사람이 먼저 해야 하는 것 둘

**이 둘이 끝나기 전에는 스크립트를 써 봐야 뜻이 없다.** 둘 다 웹 화면에서 하는 일이고
Claude 가 할 수 없다.

### ㄱ. Cloudflare 에 A 레코드

🔴 **DNS 가 와일드카드가 아니다.** 주소마다 레코드를 하나씩 넣어 왔다. 2026-10-24 실측:

```
inventory.dss21.co.kr  → 192.168.0.222   (있음)
approvals.dss21.co.kr  → 192.168.1.1     (없음 — 공유기가 대신 답한 것)
없는이름.dss21.co.kr   → 192.168.1.1     (같은 답 = 와일드카드가 아니다)
```

| 칸 | 값 |
|---|---|
| 유형 | `A` |
| 이름 | `approvals` |
| IPv4 주소 | `192.168.0.222` |
| 프록시 상태 | 🔴 **DNS 전용** (회색 구름) |
| TTL | 자동 |

🔴 **프록시 상태를 켜면(주황 구름) 안 된다.** Cloudflare 가 중계하려 드는데 대상이
**사설 IP** 라 바깥에서 닿지 않는다. 지금 아홉 레코드가 전부 DNS 전용이다.

🔵 **인증서는 손댈 것이 없다** — `*.dss21.co.kr` 와일드카드라 새 이름을 이미 덮는다
(NAS 의 acme.sh 가 매일 03:10 갱신).

**확인**: 개발 PC 에서
```
nslookup approvals.dss21.co.kr
```
→ `192.168.0.222` 가 나와야 한다. 🔵 사내 DNS 캐시 때문에 몇 분 걸릴 수 있다.

### ㄴ. DSM 역방향 프록시 규칙

**제어판 → 로그인 포털 → 고급 → 역방향 프록시**

🔴 **새로 짜지 말고 `inventory.dss21.co.kr` 규칙을 먼저 열어 보고 그대로 따라 만든다.**
아홉이 같은 모양이라, 눈으로 맞대는 것이 적어 둔 값을 믿는 것보다 안전하다.

| | 원본(Source) | 대상(Destination) |
|---|---|---|
| 프로토콜 | HTTPS | HTTP |
| 호스트 이름 | `approvals.dss21.co.kr` | `localhost` |
| 포트 | `443` | **`14000`** |

🔴 **포트는 14000 이다. 13900 이 아니다.** 13900 은 RF 이슈관리(`issues.dss21.co.kr`)가
이미 쓰고 있다(`32-rf-trouble-deploy.sh`). 개발 PC 에서 승인함이 3900 을 쓰고 있어
헷갈리기 쉬운 자리다.

🔴 **만들기 전에 NAS 에서 14000 이 정말 비었는지 센다**(저장소의 compose 사본은 낡았다 —
재고관리와 RF 이슈관리가 거기 없다). NAS 에서:
```sh
grep -n "127.0.0.1:14000" /volume1/dss/docker-compose.nas.yml ; echo "위가 비면 비어 있다"
sudo netstat -tlnp 2>/dev/null | grep ":14000 " ; echo "위가 비면 아무도 안 듣고 있다"
```

#### 🔴 규칙을 만든 뒤 — 인증서를 확인한다

**제어판 → 보안 → 인증서 → 설정**

새 역방향 프록시 규칙이 그 목록에 **새 줄로 나타난다.** 거기서 `*.dss21.co.kr` 와일드카드를
고른다. 🔴 **기본값이 DSM 의 자체 서명 인증서인 경우가 있고**, 그러면 브라우저가 경고를
띄운다. 규칙만 만들고 여기를 안 보면 놓친다.

**확인**: 사내 PC 에서 `https://approvals.dss21.co.kr` 를 연다.
- 앱을 아직 안 올렸으므로 **502** 가 맞다 — 🔵 **그것이 프록시와 인증서가 걸린 증거다.**
- 자물쇠 경고가 뜨면 인증서를 안 고른 것이다.
- 「연결할 수 없음」이면 DNS 나 프록시 규칙이 아직이다.

## 1. Dockerfile (Claude)

승인함에는 아직 `Dockerfile` 이 없다. 🔵 `next.config.ts` 에 `output: "standalone"` 은
이미 있다(실측).

🔵 본은 **`dss-board`** 가 알맞다 — 승인함처럼 **DB 가 없는** 사이트다.
🔴 `dss-auth` 를 베끼면 안 된다. 그 집의 `tools` 스테이지는 drizzle 과 마이그레이션을 담는데
승인함에는 표가 하나도 없다.

## 2. 설정 파일 `env/approvals.env` (사람 + Claude)

비밀값 셋이 필요하다. 🔴 **세 값이 서로 달라야 하고, 둘이 같으면 앱이 시작할 때 던진다.**

| 이름 | 무엇 |
|---|---|
| `SSO_CLIENT_SECRET` | 포털에 등록한 값과 같아야 한다 |
| `AUTH_SESSION_SECRET` | 세션 쿠키 서명 |
| `SSO_TX_SECRET` | 로그인 왕복 서명 |
| `SESSION_COOKIE_SECURE` | `true` (HTTPS 다) |
| `SESSION_HOURS` | 1~12 안쪽 |

🔴 `DATABASE_URL`·`PORT`·`TZ` 는 **넣지 않는다** — compose 가 넘긴다.
🔴 평문을 채팅·로그·git 에 적지 않는다. 만드는 길은 `32-rf-trouble-client.sh` 의
`--make-secret` 와 같은 꼴로 **그 자리에서 만들어 파일에 넣고 해시만 포털에 넣는다.**

## 3. compose 에 `app-approvals` 블록 (Claude)

```
ports: ["127.0.0.1:14000:3900"]
networks: [dss-edge]        # 🔵 DB 가 없으므로 dss-data 에 안 붙인다
```
🔴 블록을 더하기 전에 **사본을 뜨고**, 더한 뒤 ① 줄 수가 기대한 만큼 늘었는지 ② `image:`
줄 전체 목록이 우리 것 말고 글자까지 그대로인지 ③ `compose config -q` 가 통과하는지
④ 서비스 목록이 그대로인지를 **전부** 센다. 하나라도 어긋나면 사본으로 되돌리고 멈춘다.

## 4. 포털에 등록 (Claude 가 스크립트, 사람이 실행)

🔵 `tools-auth` 가 필요 없다 — `db-auth` 상자에 **직접 SQL** 을 넣는다
(`32-rf-trouble-client.sh` 가 그 본이다).

| 칸 | 값 |
|---|---|
| `client_id` | 🔴 **`dss-approvals`** — `dss-auth/src/lib/approvals/tile-dot.ts` 에 그 글자로 박혀 있다. 한 글자라도 다르면 **빨간 점이 영영 안 뜬다**(오류가 아니라 「아무 일도 안 일어남」이다) |
| 이름 | `DSS 통합 승인함` |
| `redirect_uri` | `https://approvals.dss21.co.kr/api/auth/sso/callback` |
| `backchannel_logout_uri` | `https://approvals.dss21.co.kr/api/auth/sso/backchannel-logout` |
| `launcher_url` | `https://approvals.dss21.co.kr` |

🔵 콜백 경로에 **`auth` 가 들어간다** — RF 이슈관리만 예외였다(`/api/sso/callback`).
승인함은 Next.js 이고 다른 여덟과 같다. 실측: `src/app/api/auth/sso/callback`.

🔴 포털은 주소를 **글자 단위로 대조한다. 와일드카드도 정규화도 없다.**

## 5. `APPROVAL_INBOX_URL` (Claude)

포털의 `env/auth.env` 에 `APPROVAL_INBOX_URL=https://approvals.dss21.co.kr` 를 넣으면
결재 메일에 주소 줄이 생긴다. 🔵 넣기 전에도 메일은 나간다.

🔵 **나중에 할 것**: 등록이 끝나면 그 주소는 `clients.launcher_url` 에도 있다. 환경변수
대신 거기서 읽는 편이 맞다(주소는 DB 에 있어야 고칠 곳이 한 곳이다 — `docs/주소.md`).
지금 그렇게 안 한 까닭은 **등록이 아직 없어서**였고, 이 단계가 끝나면 그 까닭이 사라진다.

## 6. 주기 작업 (사람 · DSM 작업 스케줄러)

결재 메일의 **뒷받침**이다. 즉시 알림이 실패한 건을 줍는다.

```
docker compose -f /volume1/dss/docker-compose.nas.yml --env-file /volume1/dss/.env.nas \
  --profile tools run --rm tools-auth npm run notify:approvals
```
🔵 10분마다를 권한다. 보낼 것이 없으면 아무에게도 묻지 않고 바로 끝난다(갈래가 전부
꺼져 있으면 더 빨리 끝난다).
🔴 **주기를 화면 글자에 박아 두지 않았다** — 여기서 바꿔도 화면이 거짓말하지 않는다.
