1 개선요청 자료 뽑기 앱 안 멈춤

마이그레이션 0104 가 개선요청 표를 통째로 지웁니다. 지운 뒤에는 되돌려 넣을 수 없어서 — 첨부를 가리키던 칸이 함께 사라집니다 — 지금 사람이 읽을 수 있는 형태로 빼 둡니다.

한 줄씩 복사하세요. 아까 명령이 여러 줄로 나뉘어 있어 붙여넣을 때 앞줄이 떨어져 나갔습니다. 아래는 전부 한 줄짜리입니다.

ㄱ. 폴더 이름을 다시 잡는다

B=$(ls -1dt /volume1/dss/backups/improvements-before-0104-* | head -1); echo "$B"

ㄴ. 첨부가 몇 건인지 센다

/usr/local/bin/docker exec dss-pg-app sh -c 'psql -U "$POSTGRES_USER" -d dss_as -Atc "select count(*) from attachments where improvement_request_id is not null"'

ㄷ. 되살릴 수 있는 꼴로

/usr/local/bin/docker exec dss-pg-app sh -c 'pg_dump -U "$POSTGRES_USER" -d dss_as -Fc -t improvement_requests' > "$B/improvement_requests.dump"

ㄹ. 사람이 읽는 꼴로 — 나중에 새 사이트에 다시 적을 때 이것을 본다

/usr/local/bin/docker exec dss-pg-app sh -c 'psql -U "$POSTGRES_USER" -d dss_as -c "\copy (select * from improvement_requests order by created_at) to stdout csv header"' > "$B/improvement_requests.csv"
/usr/local/bin/docker exec dss-pg-app sh -c 'psql -U "$POSTGRES_USER" -d dss_as -c "\copy (select id, improvement_request_id, original_file_name, stored_path, category, file_size, created_at from attachments where improvement_request_id is not null) to stdout csv header"' > "$B/improvement_attachments.csv"
🔴 칸 이름은 original_file_name 입니다. 런북에 file_name 으로 잘못 적혀 있어 2026-09-18 운영에서 ERROR: column "file_name" does not exist 로 죽었습니다. 그대로 두면 0 바이트 CSV 가 남아, 나중에 「뽑다가 실패했나」로 오해하게 됩니다. 런북은 고쳐 두었습니다.

ㅁ. 제대로 나왔는지 본다

grep -cE '^[0-9a-f]{8}-' "$B/improvement_requests.csv"; ls -l "$B"
통과 기준 — 첫 줄 결과가 16. 파일 셋이 0 바이트가 아니고, improvement_attachments.csv 는 머리글만 있는 한 줄(운영의 첨부가 0건이므로 맞습니다).
줄 수로 건수를 세지 마세요. 본문에 줄바꿈이 들어 있어 한 건이 여러 줄을 차지합니다 — 운영에서 16건이 32줄이었습니다. 그래서 wc -l 이 아니라 id 로 시작하는 줄을 셉니다.
첨부 파일 자체는 지워지지 않습니다. 디스크에 그대로 남고, 야간 백업도 지우지 않고 쌓기만 합니다. 사라지는 것은 그 파일을 가리키던 DB 줄이고, improvement_attachments.csv 의 stored_path 가 다시 찾는 열쇠입니다.

5 눈으로 확인 사람

스크립트가 통과했다고 끝이 아닙니다. 브라우저로 직접 봅니다.

  • A/S 에 로그인이 되는가 — 목록 화면까지
  • 🔴 머리말에 메뉴바 단추가 보이는가. 누르면 쓸 수 있는 시스템이 펼쳐지고, 바깥을 누르거나 Esc 로 접히는가
  • 계측기에도 같은 메뉴바가 보이는가
  • 견적서 화면에 [견적서 결재] 탭과 결재선의 「견적서」 용도가 있는가 (0105 가 들어간 표시)
  • 케이블 견적서 미리보기·받기가 나오는가
  • 포털·계측기의 평소 화면이 흔들리지 않았는가
메뉴가 안 보이면 — ① 포털이 1.4 인지 ② 로그아웃했다 다시 로그인했는지(목록은 로그인할 때만 토큰에 실립니다) ③ 그래도 안 보이면 알려주세요.

! 잘못됐을 때 되돌리기

🔴 되돌릴지 말지는 정지 창 안에서 정합니다. 스모크를 통과하지 못하면 무조건 되돌립니다.
「조금만 더 보면 될 것 같다」가 가장 비싼 판단입니다 — 그렇게 창을 넘기면 되돌리기가 사실상 불가능해집니다.

포털 · 계측기 — 이미지만 내리면 끝 (마이그레이션이 없습니다)

sed -i 's/dss-auth:1.4/dss-auth:1.3/; s/dss-meters:1.2/dss-meters:1.1/' /volume1/dss/deploy/docker-compose.nas.yml
/usr/local/bin/docker compose -f /volume1/dss/deploy/docker-compose.nas.yml --env-file /volume1/dss/deploy/.env.nas up -d --no-deps app-auth app-meters

🔴 A/S — 태그만으로는 안 됩니다. 덤프 복원이 유일한 길입니다

스크립트에 전용 모드가 있습니다. 가장 최근 pre-deploy-* 덤프로 되돌립니다.

bash /volume1/dss/setup/10-deploy.sh --rollback
이것도 20초를 셉니다. 그 덤프를 뜬 뒤에 들어온 자료는 사라집니다. 끝나면 화면이 태그를 내리는 명령 두 줄을 찍어 줍니다 — 그대로 실행하세요.
왜 A/S 만 다른가 — power_test_tasks.scope 가 NOT NULL·기본값 없음이라 옛 이미지가 통전 건명을 넣지 못하고, 0103·0104 가 지운 것은 스키마에서 아예 사라졌습니다. 이미지만 되돌리면 앱이 깨집니다.
