NAS 7단계 — 포털을 다시 띄운다 (소식이 여기서 보입니다)
🔴 빠뜨리기 쉬운 단계입니다. 업데이트 소식 글이 포털 저장소에 있어서, A/S 와 PO 만 배포해서는 소식이 안 뜹니다.
포털 교체
compose 의 app-auth 이미지 태그를 dss-auth:1.5 로 고친 뒤:
NAS 터미널 (SSH)
cd /volume1/dss/deploy
sudo docker compose -f docker-compose.nas.yml --env-file .env.nas up -d app-auth
업데이트 소식이 보이는지 확인
https://login.dss21.co.kr/release-notes — 맨 위에 PO / 내자 항목이 보여야 합니다. 로그인 없이 열립니다.
마무리 8단계 — 남은 것
「사람이 골라야 하는」 연락서를 화면에서 고른다사람
A/S → /excel-imports/kyosan-report → 후보를 보고 한 장씩. D210103 이 대표 사례입니다 — 모델·S/N·L/N 은 맞는데 고객사가 다릅니다.
직원에게 알린다사람
「견적서·내자가 PO / 내자로 옮겨졌고, A/S 에도 당분간 그대로 있다」가 가장 중요합니다. 같은 화면이 두 곳에 보이면 어느 쪽이 진짜인지 묻게 됩니다.
A/S 쪽 견적서·내자를 언제 걷어낼지는 나중에
PO 가 운영에서 도는 것을 보고 정합니다(2026-09-28 결정). 이번 배포의 범위가 아닙니다.
비상 되돌리기
무엇이 잘못됐나어떻게
연락서 이식회차 번호 하나로 통째로 — 아래 명령
POdown 하나면 끝입니다. 🔴 DB 와 첨부 폴더는 건드리지 마세요 — PO 가 올린 파일은 A/S 에서도 그대로 보입니다
A/S 앱compose 의 태그를 dss-as:1.6 으로 되돌리고 up -d app-as
포털태그를 dss-auth:1.4 로 되돌리고 up -d app-auth
연락서 — 계획만 (한 글자도 안 지웁니다)
cd /volume1/dss/deploy
sudo docker compose -f docker-compose.nas.yml --env-file .env.nas --profile tools \
  run --rm tools-as npx tsx scripts/revert-kyosan-import.ts --batch <회차>
연락서 — 계획을 읽고 승인한 뒤에만
cd /volume1/dss/deploy
sudo docker compose -f docker-compose.nas.yml --env-file .env.nas --profile tools \
  run --rm tools-as npx tsx scripts/revert-kyosan-import.ts --batch <회차> --apply
PO 내리기
cd /volume1/dss/deploy
sudo docker compose -f docker-compose.nas.yml --env-file .env.nas down app-po
✅ 되돌리기는 파일을 지우지 않고 치워 둡니다. 개발에서 실제로 써서 확인했습니다 — 4건을 되돌려 흔적 8→4 · 작업 기록 9→0 · 부품 6→0 · 첨부 84→0 이 되었고, 🔴 관계없는 보고서 1장과 다른 사람이 넣은 부품 1줄은 그대로 살아남았습니다.
