# 회사 밖에서 들어오는 길 — VPN

> ⏸ **보류 중 (2026-09-03).** 여기까지 알아내고 접었다. VPN은 6단계이고
> 그 앞에 4·5단계가 있다. **6단계를 실제로 열 때 4절부터 이어서 한다.**
> 그때까지 이 문서는 읽기만 하고 재촉하지 않는다.

6단계(접근 경계)의 절반이다. 나머지 절반인 리버스 프록시·HTTPS는 `04-리버스-프록시.md`에.

두 가지는 서로 다른 질문이다.

| | 묻는 것 | 답하는 것 |
|---|---|---|
| **이 문서** | 회사 밖에 있는 사람이 어떻게 **사내망 안으로** 들어오나 | VPN |
| `04` | 사내망 안에서 요청이 어떻게 **앱에 닿나** | 리버스 프록시 |

VPN이 사내 주소를 주기 때문에 이 둘이 갈린다. 들어온 뒤로는 사내 PC와 구별되지 않는다.

## 1. 정해진 것

| 언제 | 결정 |
|---|---|
| 2026-09-02 | **인터넷에 앱을 직접 열지 않는다.** VPN으로 사내망에 들어온 뒤 사내 주소로 쓴다 |
| 2026-09-03 | **회사 밖에서 쓸 사람은 3~5명** |
| 2026-09-03 | **계측기 관리도 회사 밖에서 쓴다** — 셋 다 VPN으로 |
| — | ⛔ **PPTP는 쓰지 않는다.** 설정이 가장 쉽지만 암호가 이미 깨진 방식이다 |

## 2. 문서 둘이 어긋난다고 적었던 것 — 어긋나지 않았다

앞선 세션이 아래 두 문장을 충돌로 적어 두었다. 실제로 읽어 보니 충돌이 아니다.

| 위치 | 문장 |
|---|---|
| `njlee/REQUIREMENTS.md:199` | ❌ **회사 밖(인터넷) 접속** — 사내망 전용 |
| `RF_Service_System/SECURITY_POLICY.md:57` | 원격지에서는 반드시 회사 VPN을 통해서만 접속한다 |

`njlee` 쪽 문장은 **"7. 이번 범위에 없는 것"의 ❌ 목록**에 있다. 뜻은 "계측기 시스템을
인터넷에 직접 노출하지 않는다"이다. VPN은 인터넷에 여는 것이 아니라 사내망에
들여보내는 것이므로 **"사내망 전용"이 그대로 성립한다.**

**정리 문장 — "VPN으로 들어온 사람도 사내에 있는 것으로 본다."**

### 이 정리가 왜 뒤 단계를 편하게 하나

VPN 사용자도 **사내 주소를 받는다.** 그래서

- 포털에 등록할 주소가 늘지 않는다 → **7단계의 「주소 넷」이 그대로다**
- 앱 설정(`SSO_ISSUER`·`SSO_REDIRECT_URI`)을 하나도 바꾸지 않는다
- 방화벽에 인터넷을 향해 낼 구멍이 **VPN 포트 하나**로 끝난다

### 고칠 곳 둘 — 6단계에서, 그 저장소의 세션과 겹치지 않을 때

문장을 뒤집는 것이 아니라 오해를 막는 한 마디를 붙이는 일이다.

| 파일 | 지금 | 붙일 것 |
|---|---|---|
| `njlee/REQUIREMENTS.md:199` | ❌ 회사 밖(인터넷) 접속 — 사내망 전용 | *"VPN으로 들어온 접속은 사내망으로 본다"* |
| `RF_Service_System/SECURITY_POLICY.md` 5절 | 원격지는 VPN을 통해서만 | VPN 사용자에게 주는 것이 **사내 IP**임을 명시 |

> 지금 고치지 않는 이유: 두 저장소에서 다른 세션이 작업 중이다. 문서 한 줄이라도
> 같은 파일을 동시에 건드리면 그쪽이 먼저 멈춘다. 결정은 여기 적어 두고 손은 나중에 댄다.

## 3. 공유기는 두 대다 (2026-09-03 확인)

| | 모델 | 자리 | CPU · RAM |
|---|---|---|---|
| 바깥 | **ipTIME A2004NS-MU** | **인터넷 선에 직접** | Realtek 1GHz · 128MB |
| 안쪽 | **ASUS RT-AC58U** | 바깥 공유기 뒤 | ARM Cortex-A7 710MHz · 128MB |

### ㄱ. 바깥 — ipTIME A2004NS-MU

인터넷에 직접 닿아 있으므로 **VPN 서버를 세울 수 있는 유일한 공유기**다.
안쪽 공유기에 세우면 포트포워딩을 두 번 걸어야 한다.

문제는 **쓸 만한 프로토콜이 없다는 것**이다.

- ipTIME은 펌웨어 **14.20.0**에서 WireGuard VPN 서버를 넣었는데,
  **지원 모델 목록에 A2004NS가 없다.** 목록은 **A3004부터 위쪽**이다
  (A3004 · A5004 · A6004 · A8004 · A9004 · AX 계열).
- ipTIME은 **OpenVPN 서버를 하지 않는다.** PPTP에서 WireGuard로 건너뛰었다.
- 그래서 남는 것은 **PPTP**, 그리고 모델에 따라 **L2TP**다.

> ⛔ **PPTP는 쓰지 않는다** — 이 저장소의 확정 사항이다. 설정이 가장 쉽지만
> 암호가 이미 깨진 방식이라, 그걸 쓰면 "VPN을 통해서만"이라는 문장이 형식만 남는다.

**L2TP/IPSec이 있으면 이야기가 달라진다.** 그건 깨진 방식이 아니고,
윈도우·아이폰·안드로이드에 **기본으로 들어 있어 따로 앱을 깔지 않아도 된다.**
이 모델에 있는지는 관리 페이지에서만 확인된다 → 4절 ㄱ.

### ㄴ. 안쪽 — ASUS RT-AC58U

- **WireGuard 없음.** ASUS의 WireGuard는 388 계열 펌웨어부터이고 주로 RT-AX 계열이다.
- OpenVPN 서버가 있더라도 **710MHz ARM에 128MB**면 처리량 천장이 낮다.
- 무엇보다 **뒤에 있어서** 인터넷에서 여기까지 오려면 포워딩을 두 번 거쳐야 한다.

→ **이 공유기는 VPN 후보에서 뺀다.** 자리도 성능도 맞지 않는다.

### ㄷ. 그래서 기울어진 곳 — NAS

공유기 둘 다 편하지 않다. 반면 **DS218+의 Celeron J3355는 AES-NI**(암호화 전용 명령)를
가지고 있어 같은 일을 훨씬 싸게 한다. 공유기는 **포트포워딩 한 줄**만 맡으면 되고,
그건 A2004NS-MU가 확실히 하는 일이다(포트포워드·DMZ 지원).

**바뀐 것을 분명히 해 둔다.** 앞선 세션은 *"공유기가 지원하면 NAS 부담 없이 가장
깔끔하다"* 고 적었다. 그 전제는 **공유기가 그 일을 감당할 때** 맞다.
여기 있는 두 대는 그렇지 않다 — 부담을 더는 대신 **더 낮은 천장으로 옮기는 것**이 된다.

### ㄹ. 아직 모르는 구조 — 이것이 남은 진짜 질문이다

공유기가 둘이라는 사실이 새 질문을 만든다.

| | 물음 | 왜 중요한가 |
|---|---|---|
| 1 | RT-AC58U가 **라우터 모드인가 AP 모드인가** | 라우터 모드면 **이중 NAT**다. 뒤쪽 장비로 가는 포워딩이 두 겹이 된다 |
| 2 | **NAS는 어느 공유기에 물려 있나** | 안쪽(ASUS)에 물려 있으면 포워딩을 두 번 걸어야 한다 |

> **가장 깔끔한 정리** — RT-AC58U를 **AP 모드**로 바꾸면 NAT가 한 겹이 되고
> 사내가 한 망으로 합쳐진다. 그러면 포워딩도 한 줄로 끝난다.
> 다만 이건 **사내 네트워크 전체를 건드리는 일**이라 6단계에서 따로 판단한다 —
> 지금 결정할 것이 아니다.

## 4. 아직 모르는 것 — 사람이 확인한다

### ㄱ. 바깥 공유기(ipTIME A2004NS-MU) 관리 페이지에서

`http://192.168.0.1` (ipTIME 기본 주소). **인터넷에 직접 닿은 쪽이라 여기가 중요하다.**

| | 볼 곳 | 적을 것 |
|---|---|---|
| 1 | **고급 설정 → 특수 기능 → VPN 서버 설정** | 무엇이 있나 — PPTP만인가, **L2TP도 있는가** |
| 2 | 첫 화면 **인터넷 연결 정보 → 외부 IP 주소** | 그 숫자 |
| 3 | **시스템 관리 → 펌웨어 업그레이드** | 현재 버전, 새 버전이 있는가 |

**1번이 이 확인의 핵심이다.** `L2TP`가 있으면 공유기 길이 다시 열린다 —
윈도우·아이폰·안드로이드에 기본으로 들어 있어 앱을 깔 필요가 없다.
`PPTP`만 있으면 **공유기 길은 닫힌다**(3절 ㄱ의 ⛔).

### ㄴ. 두 공유기가 어떻게 이어져 있나

| | 볼 곳 |
|---|---|
| 1 | RT-AC58U 관리 페이지 → **동작 모드**가 「무선 라우터」인가 「액세스 포인트(AP)」인가 |
| 2 | **NAS의 랜선이 어느 공유기에 꽂혀 있나** |

둘 다 "안쪽 ASUS"로 나오면 포워딩이 두 겹이 된다 → 3절 ㄹ.

### ㄷ. 공인 IP인가

위 ㄱ 2번의 외부 IP와, 같은 PC에서 `https://ifconfig.me` 를 열었을 때 나오는 IP를 **대조한다.**

| | 뜻 | 결과 |
|---|---|---|
| **두 IP가 같다** | 바깥 공유기가 인터넷에 직접 닿아 있다 | 포트포워딩이 통한다 |
| **두 IP가 다르다** | 통신사 장비가 하나 더 있거나 CGNAT다 | 포트포워딩이 안 통한다 → **메시 VPN만 남는다** |

### ㄹ. 업로드 속도

**사내 PC에서 유선으로**, 다른 사람이 큰 파일을 올리고 있지 않은 때에 잰다.

1. `https://fast.com` 을 연다
2. 결과가 나오면 **"자세히 보기(Show more info)"** 를 누른다 — 이걸 눌러야 업로드가 나온다
3. **업로드(Upload)** 숫자를 적는다. 다운로드가 아니다

`speedtest.net`도 된다. 둘 다 재서 낮은 쪽을 기준으로 삼는다.

| 업로드 | 밖에서의 체감 |
|---|---|
| 100Mbps 이상 (대칭) | 사내와 거의 같다 |
| 20~100Mbps | 화면 넘기기는 문제없다. 사진 여러 장·PDF에서 기다림이 보인다 |
| 20Mbps 미만 | A/S 보고서 PDF와 계측기 사진에서 체감이 확실히 떨어진다 |

> **왜 업로드인가** — 밖에서 화면을 볼 때 회사는 **보내는 쪽**이다.
> 회사 회선의 업로드가 곧 밖에 있는 사람의 다운로드다. CPU도 NAS도 병목이 아니다.

## 5. 갈림길 — 공유기 길이 거의 닫혔다

공유기 둘의 사정이 드러나면서 **NAS 쪽으로 기울었다.** 공유기가 다시 후보가 되는
경우는 하나뿐이다 — ipTIME에 **L2TP**가 있을 때. 무엇을 고를지는
**4절 ㄱ 1번(L2TP 유무)** 과 **ㄷ(공인 IP 여부)** 이 정한다.

| 확인 결과 | 택할 것 | 무게 |
|---|---|---|
| 공인 IP **아님** (CGNAT) | **메시 VPN** (NAS의 Tailscale 등) | 다른 조건을 볼 것 없이 여기로 온다 |
| 공인 IP + ipTIME에 **L2TP 있음** | 공유기 L2TP/IPSec **또는** NAS | 앱을 안 깔아도 되는 이점 ↔ 공유기 성능. 아래 저울 |
| 공인 IP + **PPTP만 있음** | **NAS**의 Synology VPN Server | 공유기 길이 닫힌다. 남는 자리는 NAS뿐 |

### L2TP가 있을 때의 저울

| | 공유기 L2TP | NAS VPN Server |
|---|---|---|
| 쓰는 사람 | **앱을 안 깐다.** 윈도우·아이폰 기본 설정에서 붙는다 | 앱을 깔거나 프로파일을 받는다 |
| 성능 | Realtek 1GHz가 암호화를 진다 | **AES-NI**가 있다. 자릿수가 다르다 |
| NAS 부담 | 없다 | Postgres 둘 + 앱 셋 위에 얹힌다 |
| 회선이 느리면 | **차이가 사라진다** — 병목이 회선이므로 | 같음 |

> **회선 업로드가 20Mbps보다 느리면 공유기 쪽이 낫다.** 그 아래에서는 공유기의
> 낮은 천장이 병목이 아니고, NAS를 비워 두는 이득만 남는다.
> 그보다 빠르면 공유기가 회선을 버리기 시작하므로 NAS로 옮긴다.

### 왜 업로드 속도로 재는가

밖에 있는 사람이 겪는 속도는 **회선의 업로드**와 **암호화를 지는 장비의 처리량** 중
**낮은 쪽**이다. 회선이 10Mbps인데 장비가 15Mbps를 낸다면 장비를 바꿔도 체감은
그대로다. 반대로 회선이 100Mbps인데 장비가 15Mbps라면 **회선의 대부분을 장비가
버리고 있는 것**이다. 그때 NAS로 옮기면 그만큼이 돌아온다.

### NAS로 가게 되면 함께 할 일

| | 할 일 |
|---|---|
| 1 | `01-postgres-통합.md` 8절 **자원 예산**을 다시 계산한다 — Postgres 둘 + 앱 셋 위에 VPN이 얹힌다 |
| 2 | **바깥 공유기(ipTIME)에** 포트포워딩. 안쪽 ASUS 뒤에 NAS가 있으면 두 겹이 된다 → 3절 ㄹ |
| 3 | 두 공유기 **펌웨어를 최신으로.** 포트를 인터넷에 여는 일이다 |

### 메시 VPN(Tailscale 등)을 택하게 되면

- Synology 패키지 센터에서 찾을 수 있다. 없으면 공식 SPK를 받는다.
- **포트포워딩도 공인 IP도 필요 없다.** 이중 NAT·CGNAT를 그대로 통과한다 —
  공유기가 둘인 지금 구조에서 이 점이 특히 크다.
- 사내의 다른 장비까지 닿게 하려면 **서브넷 라우팅**을 켠다. NAS만 쓸 것이면 필요 없다.
- ⚠️ **무료 범위가 「인원」으로 갈리고 그 기준이 몇 번 바뀌었다.** Tailscale 무료
  (Personal)는 사용자 수 상한이 있어 **5명이면 걸릴 수 있다.** 이 길을 택하는 시점에
  **직접 요금제를 확인하고** 고른다 — 여기 적힌 숫자를 믿지 않는다.

## 6. 아직 답하지 않은 것

- 밖에서 쓸 3~5명의 **장치**가 무엇인가 (노트북 / 아이폰 / 안드로이드).
  IPSec만 있는 공유기라면 이것이 방식 선택을 바꾼다.
- 누가 언제 들어왔는지를 **남길 것인가.** 6명을 넘지 않으므로 지금은 필수가 아니지만,
  나중에 붙이려면 방식에 따라 갈아엎어야 할 수 있다.
- NAS VPN을 택하게 되면 `01-postgres-통합.md` 8절 **자원 예산**을 다시 계산한다.
