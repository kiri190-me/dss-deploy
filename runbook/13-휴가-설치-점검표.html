1. 포털에 등록한다

운영 포털에 dss-leave 를 넣는다 사람
NAS 에서 ssh dss-nas → sudo -i 한 뒤: 
sh /volume1/dss/setup/13-leave-client.sh
이미 있으면 최신으로 맞춥니다(두 번 돌려도 안전). 봐 주실 것: 해시앞이 18783c276efd · 해시길이가 64 · 주소 셋이 전부 https://leave.dss21.co.kr
⚠️ requires_grant 가 f 입니다 — 전 직원이 바로 봅니다. PO 때처럼 명단(--grant)을 따로 넣을 일이 없습니다.

2. 비밀번호를 한자리에서 정한다

🔴 같은 값이 세 곳에 들어갑니다. 한 번에 하는 이유입니다.
① NAS 의 DB 롤 dss_leave_app ② .env.nas 의 LEAVE_APP_PASSWORD ③ compose 가 그 값으로 DATABASE_URL 을 조립
한 글자라도 다르면 앱 로그에 password authentication failed 가 찍힙니다.
DB 롤에 비밀번호를 넣는다 사람
입력한 글자는 화면에 보이지 않습니다.
sh /volume1/dss/setup/13-leave-pw.sh
🔴 정한 값을 손에 들고 계세요. 바로 다음에 .env.nas 에 같은 값을 적습니다.
.env.nas 에 LEAVE_APP_PASSWORD 한 줄을 더한다 사람
/volume1/dss/deploy/.env.nas 는 root 600 입니다. 그 파일에 한 줄을 더합니다 — 스크립트가 안내합니다(값은 스크립트에 안 적습니다). 
sh /volume1/dss/setup/13-leave-env.sh

3. 설정 파일을 만든다

leave.env 를 완성한다 Claude
지금 SSO_CLIENT_SECRET 한 줄뿐입니다. 나머지를 채웁니다 — SSO_ISSUER · SSO_REDIRECT_URI · SSO_TX_SECRET(새로 만듦) · SESSION_* 등.
🔴 DEV_FAKE_LOGIN_ENABLED 를 반드시 끕니다. 켜진 채 나가면 아무나 남의 계정으로 들어갈 수 있습니다.
🔴 DATABASE_URL · PORT 는 넣지 않습니다 — compose 와 이미지가 넘깁니다.
compose 에 서비스 둘을 더한다 Claude
app-leave(포트 127.0.0.1:13700)와 tools-leave(profiles: [tools]). 개선요청(app-improvements)이 본보기입니다 — 자기 DB · 전 직원 공개 · 업로드 폴더 없음.
⚠️ tools-leave 에 DATABASE_URL 을 반드시 넣어야 합니다. 없으면 「.env.local 파일을 확인하세요」라는 개발 PC 용 문구로 죽어서 NAS 에서 보면 오해하기 쉽습니다.
야간 백업에 dss_leave 를 더한다 Claude
🔴 오늘 개선요청이 이것 때문에 11일간 백업되지 않았습니다. 저장소에는 더해 놓고 NAS 에 그 파일을 안 올렸습니다. 고치는 것과 올리는 것은 다른 일입니다 — 아래 4단계에서 올린 것까지 확인합니다.

6. 띄운다

🔴 여기부터가 진짜 설치입니다. 앞의 것이 하나라도 안 끝났으면 넘어오지 마세요.
다른 사이트는 멈추지 않습니다 — 새 서비스를 하나 더 띄우는 것뿐입니다.
읽기만 — 어긋난 곳이 없는지 사람 
bash /volume1/dss/setup/13-deploy.sh
인자 없이 돌리면 아무것도 안 바꿉니다. 이미지 지문 · 설정 파일 · compose · DB 와 롤 · 백업 · 주소를 봅니다. 실패 0 이어야 다음으로 갑니다.
이미지를 싣는다 (앱 안 멈춤) 사람 
bash /volume1/dss/setup/13-deploy.sh --preload
md5 를 먼저 맞추고(어긋나면 안 싣습니다), 실은 뒤 지문을 대조하고, 도구 이미지 안의 마이그레이션이 2개인지 셉니다.
표를 만들고 직급을 넣는다 사람
🔴 순서가 있습니다 — 표가 있어야 직급이 들어갑니다. 스크립트가 db:migrate → seed:ranks 로 부릅니다. 
bash /volume1/dss/setup/13-deploy.sh --init
마이그레이션 2개가 들어가고 직급이 채워집니다. seed:ranks 는 여러 번 돌려도 중복이 안 생깁니다.
앱을 띄운다 사람 
bash /volume1/dss/setup/13-deploy.sh --go
app-leave 하나를 띄우고 응답을 기다립니다. 다른 다섯은 그대로 돕니다.

🔴 직급이 비어 있으면 직원을 한 명도 등록할 수 없습니다. 6-③ 이 제대로 됐는지는 이걸로만 확인됩니다.
🔴 알림 링크가 밖에서 닿는가 사람
오늘 개선요청이 여기서 걸렸습니다. 휴가에서 결재 알림이 생기게 한 뒤, A/S 나 개선요청의 종에서 그 줄에 마우스를 올려 주소를 보세요.

(휴가는 SSO_REDIRECT_URI 에서 자기 주소를 뽑는 올바른 방식이라 괜찮을 것으로 봅니다. 그래도 눈으로 봅니다.)
메뉴바와 알림 종이 보이는가 사람
안 보이면 고장이 아니라 재로그인 문제일 수 있습니다. 한 번 로그아웃하고 다시.
🔴 알림이 하나도 없으면 종은 원래 안 보입니다(빈 종을 안 그리는 설계). 오늘 그걸 결함으로 오해할 뻔했습니다.

되돌리기

무엇이 잘못됐나어떻게
앱이 안 뜬다 bash /volume1/dss/setup/13-deploy.sh --rollback — app-leave 를 내리고 compose 를 옛것으로 되돌립니다. DB 와 포털 등록은 남겨 둡니다(해가 없고, 다시 띄울 때 그대로 씁니다).
마이그레이션이 잘못 들어갔다 오늘 백업으로 dss_leave 만 복원합니다. 다른 DB 는 안 건드립니다 — 휴가는 자기 DB 를 씁니다.
포털 타일을 숨기고 싶다 update clients set is_active = false where client_id = 'dss-leave';
지우지 말고 끄세요. 시크릿과 등록값이 남아 다시 켜기 쉽습니다.
주소가 안 열린다 Cloudflare 레코드 · DSM 프록시 · 인증서 셋 중 하나입니다. 502 면 앱 문제, 인증서 경고면 5단계 ③, 아예 안 잡히면 DNS 입니다.
🔴 되돌릴 수 없는 것 하나 — seed:ranks 로 들어간 직급은 되돌리는 명령이 없습니다. 다만 직급만 넣고 사람 자료는 안 건드리므로 실질적 위험이 없습니다.

오늘 배운 것 — 이 설치에 그대로 쓰입니다

「있는가」가 아니라 「제 일을 하는가」를 봅니다. 오늘 같은 함정에 네 번 걸렸습니다.
  • 폴더는 주인이 맞는데 ACL 이 막아 컨테이너가 못 읽었다
  • 이미지는 이름표가 맞는데 속이 8일 전 판이었다
  • 통로는 응답이 오는데 내주는 주소가 컨테이너 것이었다
  • 백업은 문서에 「더했다」고 적혀 있는데 NAS 에 안 올렸다(11일간)
넷 다 오류가 안 났습니다. 그래서 이 점검표는 결과를 봅니다 — 폴더는 컨테이너 안에서 열고, 이미지는 안의 파일을 세고, 주소는 받아 보고, 백업은 다음 날 아침에 다시 봅니다.
