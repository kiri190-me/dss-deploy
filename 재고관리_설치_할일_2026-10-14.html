지금 어디까지 됐나

코드와 배포본은 다 준비됐습니다. NAS 에서는 아직 아무것도 실행하지 않았습니다 — 운영 일곱 사이트는 그대로 돌고 있습니다.
  • 배포 스크립트 여섯 작성 (27-*.sh)
  • 직원이 현황판 엑셀을 읽을 공유폴더 자리 결정 · 코드 반영
  • 이미지 둘 굽기 → tar → NAS 로 올림 (md5 대조 완료)
  • tar 지문 넷을 스크립트에 채움
  • 26번 배포 뒤 바뀐 운영 태그 맞춤 (포털 1.7 · 게시판 0.2)
  • ↓ 여기서부터가 아래 할 일입니다
인계 자료는 이미 있습니다. 바탕화면\Development\재고관리 인계 (2026-10-12) 에 엑셀 양식 두 벌·전환일 입력 둘·절차서가 들어 있습니다.
그중 재고 및 견적 현황판 틀_과거줄포함.xlsx 는 단순 양식이 아니라 과거 기록이 값으로 든 자료 그 자체입니다(사용처 1,652줄 · 입고 662줄). 잃으면 다시 못 만듭니다.

할 일 — 이 순서대로

순서를 지켜 주세요. 특히 4번(포털에 사람 등록)이 빠지면 사이트가 서도 아무도 못 들어갑니다. 이 시스템은 처음 로그인인데 역할이 없으면 거절하고, 다른 시스템에 있는 비상구(make:admin)가 없습니다.

  1. Cloudflare 에 주소 하나 추가 사용자

    dss21.co.kr 의 DNS 에 A 레코드를 하나 더합니다. 다른 일곱(login·as·po 등)과 같은 모양입니다.

    이름inventory
    값NAS 사설 IP (192.168.0.222) — 기존 일곱과 같은 값
    프록시끔 (DNS only) — 기존 일곱과 같게

  2. DSM 리버스 프록시 추가 사용자

    DSM → 제어판 → 로그인 포털 → 고급 → 역방향 프록시.

    원본HTTPS · inventory.dss21.co.kr · 포트 443
    대상HTTP · localhost · 포트 13800
    인증서dss21.co.kr (기존 것 그대로)
    앱을 띄우기 전에 열면 502 가 뜨는 것이 정상입니다. 고장이 아닙니다.

  3. 설정 파일과 비밀값 준비 제가

    제가 만들어 NAS 로 올립니다. 사용자께서 하실 일은 없습니다.

    • inventory.env — 비밀값 셋을 새로 만들어 넣습니다
    • 포털 등록용 해시 (평문은 어디에도 안 적습니다)
    • compose · 야간 백업 스크립트를 NAS 로
    1·2번이 끝나면 알려 주세요. 그때 제가 이것을 합니다.

  4. NAS 에서 스크립트 돌리기 사용자

    NAS 의 docker 는 root 가 필요해서 제가 못 합니다. PowerShell 에서:

    ssh dss-nas
sudo -i                      # DSM 비밀번호 · 한/영이 영문인지 보세요

    그다음 NAS 안에서 이 차례로:

    # ① DB 와 롤 만들기
sh /volume1/dss/setup/27-inventory-db.sh
sh /volume1/dss/setup/27-inventory-pw.sh

# ② 포털에 재고 관리 등록
sh /volume1/dss/setup/27-inventory-client.sh

# ③ 파일을 제자리에 놓고 폴더 만들기
sh /volume1/dss/setup/27-inventory-place.sh

# ④ 설치 — 읽기 → 싣기 → 읽기 → 표 만들기 → 띄우기
bash /volume1/dss/setup/27-deploy.sh
bash /volume1/dss/setup/27-deploy.sh --preload
bash /volume1/dss/setup/27-deploy.sh
bash /volume1/dss/setup/27-deploy.sh --init
bash /volume1/dss/setup/27-deploy.sh --go
    ④의 다섯 줄은 한 줄씩 돌리고 결과를 저에게 붙여 주세요. 제가 읽고 다음으로 가도 되는지 판단하겠습니다.
    --init 은 DB 가 바뀌는 단계입니다(표 열셋을 만듭니다). 그 전까지는 아무것도 안 바뀝니다.
    돌리는 중 다른 일곱 사이트는 안 멈춥니다. 새로 하나가 서는 것뿐입니다.

  5. 포털에 쓸 사람 등록 사용자

    이것이 없으면 사이트가 서도 아무도 못 들어갑니다. 4번 ②가 등록하는 것은 시스템이고, 여기서 넣는 것은 사람입니다. 둘 다 필요합니다.

    포털(https://login.dss21.co.kr) 관리 화면에서 정영빈 님을 재고 관리의 ADMIN 으로 넣습니다.

    시스템DSS 재고 관리 (dss-inventory)
    사람정영빈
    역할ADMIN
    나머지 분들은 급하지 않습니다 — 정영빈 님이 「전환일에는 저 하나로 시작할 수 있다」고 하셨습니다. 역할은 VIEWER / STAFF / ADMIN 셋입니다.

  6. 화면을 열어 확인 사용자

    https://inventory.dss21.co.kr 에 정영빈 님 계정으로 들어가 봅니다.

    • 로그인이 되는가 (포털을 거쳐 들어옵니다)
    • 첫 화면이 뜨는가 — 자료는 아직 비어 있는 것이 정상입니다
    • 포털 첫 화면에 📦 DSS 재고 관리 타일이 보이는가

설치가 끝난 뒤 — 전환일까지

정영빈 님이 「야간 백업에 들어갔다는 확인이 되기 전에는 실자료를 넣지 않는다」고 못 박으셨습니다. 그래서 순서가 정해져 있습니다.
순서무엇누가
①야간 백업을 한 번 돌려 재고 관리 몫이 찍히는지 본다제가
②정영빈 님께 「백업 들어갔습니다」 답을 드린다 (요청문 1번)제가
③엑셀 양식 두 벌과 전환일 입력 둘을 NAS 에 넣는다제가
④전환일 — 실자료 수천 줄을 넣는다. 별도의 날, 전용 절차서가 있다함께
④는 한 번만 돌릴 수 있고, 되돌리려면 DB 를 비워야 합니다. 사람이 숫자를 대조하며 하는 작업이라 설치와 같은 날 하지 않습니다.

알아 두실 것

현황판 엑셀은 공유폴더에 생깁니다

프로그램이 1분마다 현황판 엑셀을 다시 씁니다. 직원분들이 탐색기로 여는 자리는 여기입니다:

2_AS센터 \ 2. 부품 관리 \ 1. 재고 및 부품 입출고 관리 \ 4. 재고관리 시스템
그 폴더는 설치 때 새로 만들어집니다. 옆의 기존 폴더 셋 (1. AS 관련 부품 · 2. CS 재고 관리 · 3. 이전 관리 자료)은 건드리지 않습니다.

잘못되면 되돌릴 수 있습니다

설치는 새 사이트를 하나 더 세우는 것이라 기존 일곱에 영향이 없습니다. 문제가 생기면 이 줄로 되돌리는 방법이 나옵니다:

bash /volume1/dss/setup/27-deploy.sh --rollback

제가 못 하는 일

NAS 의 docker 와 권한 작업은 root 가 필요합니다. 제 계정(swhur)에는 그 권한이 없고, 비밀번호 없는 sudo 를 주면 이 PC 의 열쇠 파일 하나가 NAS 전체 열쇠가 되기 때문에 그렇게 하지 않기로 2026-09-14 에 정했습니다. 그래서 4번은 사용자께서 치셔야 합니다. 파일을 올리고 로그를 읽는 것은 제가 합니다.
