## 왜 지금 옮기지 않나

**매일 쓰는 런처라, 옮기면 그날 바로 깨진다.** 옮기려면 세 가지를 함께 고쳐야 한다.

1. `작업 시작.cmd`의 `%~dp0start-menu.ps1` → 새 경로
2. `작업 종료.cmd`의 `%~dp0end-all.ps1` → 새 경로
3. 각 ps1의 `$DevRoot = $PSScriptRoot` → 두 단계 위를 가리키도록
   (`scripts/` 안으로 들어가면 `$PSScriptRoot`가 더 이상 `Development/`가 아니다)

NAS 이식 중에 런처가 깨지면 그날 작업이 통째로 막힌다.
이식이 끝나고 손이 빈 날에 한 번에 옮기는 편이 안전하다.

## 옮길 때 지킬 것

- **복사본을 만들어 두 벌로 두지 않는다.** 갈라지면 어느 쪽이 진짜인지 알 수 없게 된다.
  옮기고, 경로를 고치고, 한 번 돌려 보고, 커밋한다.
- 옮긴 뒤 `작업 시작.cmd`로 **메뉴 0번(전부 한 번에)까지 실제로 돌려 본다.**
  경로 하나만 틀려도 창이 조용히 닫힌다.
- 이 스크립트들은 **개발 PC 전용**이다. NAS는 Linux라 PowerShell이 돌지 않는다.
  NAS용 배치가 필요하면 셸 스크립트로 따로 쓴다.
